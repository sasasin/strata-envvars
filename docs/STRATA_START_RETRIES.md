# `STRATA_START_RETRIES`

調査対象: Strata `main` の HEAD `296b59d2f73c8f04a805df29c2fa97655adace78`（2026-10-14 時点）。

## 役割

`serve/server.py` が起動する常駐 Strata エンジンについて、GPU ランタイムの一時的な初期化失敗と判定した場合に、READY を返す前の起動を何回まで再試行するかを指定します。ROCm で直前のエンジン終了後、前プロセスの GPU queue が解放中のため次の起動が失敗する状況などを想定しています。通常の起動失敗全般や READY 待ち timeout を再試行する設定ではありません。

## 値と判定

サーバーモジュールの import 時に `os.environ.get("STRATA_START_RETRIES", "3") or 0` を `int()` に渡し、結果と 0 の大きい方を `START_RETRIES` として保存します（`serve/server.py:526-528`）。

| 環境変数の状態 | 結果 |
|---|---|
| 未設定 | 既定文字列 `"3"` を整数化し、最大 3 回再試行 |
| 空文字 | `or 0` により 0 となり、再試行なし |
| 0 または負の整数 | 0 回（負数は `max(0, ...)` で 0 にする） |
| 正の整数 | その回数まで再試行 |
| 整数として解釈できない文字列 | `int()` の `ValueError`。値の読み取りは import 時のため、サーバーモジュールの import を失敗させる |

Python の `int()` による整数変換で、浮動小数点表記は受け付けません。環境変数を数値として扱う前に空白除去や独自の文字列比較はしていません。空白だけの文字列も空文字ではないため `int()` に渡され、変換エラーになります。

## 有効になる条件

再試行にはすべて次の条件が必要です（`serve/server.py:863-865`, `531-552`）。

- エンジンが `READY` を返さず起動に失敗したが、READY timeout ではない。
- 今回の起動からの経過時間が 30 秒以内。
- ログファイルが指定され、起動時のログ範囲を読み取れる。
- そのログ範囲にエンジン自身の通常のエラー出力がない。
- ランタイム失敗マーカー（`hsa_exception`, `HSA_STATUS_ERROR`, `hsaKmt`）があれば、エンジン自身の行が `terminate called`、`what()`、またはマーカーを含む行に限られる。マーカーがない場合はエンジン自身の行がなく、終了コードが 1 ではなく、`engine_crashed()` の判定でもない。
- `_attempt < START_RETRIES` である。

したがって、通常のエンジン設定エラー、READY timeout、ログなし、30 秒を超えた起動失敗はこの値による再試行の対象外です。設定値が正でも、上記条件を外れれば再試行しません。

## 実行時の詳細

再試行対象なら、初回の後に 2 秒待ち、以降は試行ごとに待ち時間を倍にして 4 秒、8 秒……とします。再帰的に `StrataEngine` を作り直し、`_attempt` を 1 増やして起動します（`serve/server.py:863-879`）。既定値 3 は「初回を含む起動試行数」ではなく「追加の再試行数」で、最大 4 回起動します。

ログに GPU ランタイムのマーカーがあるときはランタイム初期化中に停止した旨を stdout に出し、マーカーがなくログ行もないときはログに何も書く前に終了した旨と、ランタイムがまだ準備できていなかった可能性を出します。どちらも次の試行までの秒数と「try N of M」を表示します（`serve/server.py:867-876`）。再試行を使い切るか条件を満たさない場合は `EngineDied` を送出します（`serve/server.py:880-890`）。

値は Python サーバーのモジュール import 時に一度だけ評価されます。同じプロセス内で環境を変更しても再評価されません。子エンジン起動時の環境引き渡しは別処理で行われますが、この変数を子エンジンが読むコードは見つかりません。対象ソース内の直接参照は `serve/server.py` の設定と再試行処理にあり、テスト内の参照はテスト用モックです。
