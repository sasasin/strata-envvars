# `STRATA_DUMP_NGL`

調査対象: Strata `main` の HEAD `477ac13cbe8e582c20484871ce459d20d82df09d`（2026-10-17 時点）。

## 役割

同梱の Qwen3.6 比較用ツール `tools/qwen35/q36_llama_dump.cpp` で、コマンドラインの `--ngl` が正の値のときに GPU レイヤー数を上書きします。コメントによると、GPU を使う指定でモデルファイルが VRAM に収まらない場合に、GPU に載せるレイヤー数を減らすためのフックです。Strata の通常の実行ファイルが読む設定ではありません。

## 値と判定

環境変数は `main()` の引数処理後、モデル読み込み前に一度読みます。未設定なら `--ngl` の値（省略時は `99`）がそのまま使われます。設定されていても、CLI の `--ngl` が `0` 以下なら環境値を読み取った後の上書き条件を満たさず、CLI 値が維持されます。

`--ngl > 0` の場合、環境値を `std::atoi()` に渡して `ngl` を置き換えます。文字列全体の検証や範囲制限、エラー報告はありません。したがって空文字や数字で始まらない文字列は通常 `0` になり、数値の接頭部分は整数に変換されます（例: `12tail` は `12`）。負数もそのまま代入されます。変換後の値が正であることは再確認されません。

| CLI `--ngl` | `STRATA_DUMP_NGL` | 最終的な `ngl` |
|---|---|---|
| 省略（既定 `99`）または正数 | 未設定 | CLI 値 |
| 省略または正数 | 設定あり | `std::atoi()` の変換結果 |
| `0` または負数 | 未設定・設定あり | CLI 値 |

## 有効になる条件

この変数を読むのは `tools/qwen35/q36_llama_dump.cpp` の `q36_llama_dump` だけです。ファイル先頭のビルド例は llama.cpp checkout のヘッダーとライブラリにリンクする単独ビルドを示しており、このソースは Strata の通常の build target には組み込まれていません。`tools/qwen35/parity.py` は `q36_llama_dump` を外部プロセスとして呼び出しますが、`--ngl` を渡すだけで `STRATA_DUMP_NGL` を設定・転送する処理はありません。呼び出し元プロセスから環境が継承される場合に限り、このツール内で値が読まれます。

## 実行時の詳細

上書き後の `ngl` は llama.cpp の `llama_model_params.n_gpu_layers` に設定されます。また `ngl > 0` のときだけ `llama_context_params.op_offload` が true になります。環境値が `0` または負数へ上書きした場合、後者は false になります。モデル読み込み失敗時にはツールが `cannot load <model>` を stderr に出して終了コード `1` を返しますが、これは環境変数固有のエラーではありません。

ここで確認できるのは Strata 同梱ソースによる読み取りと llama.cpp API パラメーターへの設定までです。指定されたレイヤー数を実際にどう配置するかという llama.cpp 側の動作は、この調査の対象外です。
