# `STRATA_DS4_SLOT_KEEP`

調査対象: Strata `main` の HEAD `7dd5cf18e68c639a8773e096c5c79f971ea2a9f5`（2026-10-25 時点）。外部ライブラリの環境変数は対象外。

## 役割

DeepSeek-V4.1 の `maya-ds4` エンジンが、別の会話へ切り替えるときに現在の会話状態を退避し、後続の入力がその会話を続ける場合に状態を復元する機能を有効にします。退避対象にはモデル状態と token/checkpoint 情報が含まれます。RAM 上の保持数を超えた状態やエンジン終了時の状態はスロットフォルダーへ保存され、次回起動後にも再利用できます。

設定の既定値は起動経路で異なります。`maya-ds4` を直接起動した場合は未設定で無効です。`serve/server.py` から `arch == "deepseek41"` のエンジンを起動する場合、サーバーはこの変数が未指定なら `"1"` を子プロセス環境に追加します。

## 値と判定

エンジンは `getenv()` で値の有無を確認し、設定されている場合は `atoi()` の結果が 0 以外かを判定します。したがって文字列全体の厳密比較ではなく、`atoi` が先頭から読める整数部分で決まります。

| 環境値 | エンジンでの判定 |
|---|---|
| unset | 無効（直接起動時）。サーバー起動ではサーバーが通常 `"1"` を補う |
| 空文字 | 無効（`atoi("") == 0`） |
| `1`, `2`, `-1`, `1abc`, ` 1` | 有効（変換結果が 0 以外） |
| `0`, `0abc`, `abc`, 空白のみ | 無効（変換結果が 0） |

数値の範囲検査やエラー通知はありません。値は `serve()` 開始時に一度評価されます。実行中にプロセス環境を書き換えても、この設定は再評価されません。

## 有効になる条件

- 対象は `src/dsv41/ds4_main.cpp` の `serve()` 経路です。ほかの Strata エンジンのスロット機能を制御する変数ではありません。
- `STRATA_DS4_SLOT_KEEP` が有効でも、会話が `STRATA_DS4_SLOT_MIN`（既定 1024 token）未満なら退避されません。画像を含む会話は退避対象外で、画像付き prompt は保存スロットを取り出しません。
- RAM 保持上限は `STRATA_DS4_SLOT_CAP`（エンジン既定 4）です。フォルダーの上限は `STRATA_DS4_SLOT_GB`（エンジン既定 16 GiB相当）で、期限は `STRATA_DS4_SLOT_DAYS`（既定 7 日）です。これらは関連する別変数です。
- スロットフォルダーは `STRATA_DS4_SLOT_DIR` が設定されればその場所、未設定なら `<pack>/slots` です。フォルダーを作成できない、またはディレクトリとして確認できない場合、stderr に `ds4 slots: <path> is not writable - conversations are not set aside` と出し、スロットを無効化します。保存時に空き容量が 8 GiB 未満ならファイルへ書かず、書き込みに失敗した RAM スロットは退避処理の呼び出し元で破棄される場合があります。
- サーバー起動では、環境変数の子プロセス用コピーにまず親プロセス環境を取り込み、設定ファイルの `cfg["env"]` を上書き適用します。その後 DeepSeek-V4.1 の場合だけ `setdefault` で既定値を補うため、明示した設定ファイル値またはシェル環境値が優先されます。サーバーはこの経路で `STRATA_DS4_SLOT_GB=2` も補い、ログがあれば `STRATA_DS4_SLOT_DIR` をログ隣の `ds4-slots` に設定します。

## 実行時の詳細

新しい prompt が現在の会話を続けない場合、エンジンは現在の会話を `slot_save()` で退避し、prompt と token/checkpoint が合う保存済み会話を探します。RAM 上の状態または `.bin` ファイルから `slot_load()` で復元し、prompt が会話全体でなく既知の checkpoint まで戻る場合はそこまで復元して残りの prompt を読みます。該当する保存状態がない場合は通常どおり prompt を読みます。切替え時や復元時の状況は stderr の `ds4 slots: ...` と stdout の `NOTE sessions: ...` に出力されます。

ディスク保存時には state の `.bin` と会話 token・モデル識別情報を持つ `.meta` が使われます。起動時に不完全、別モデル、サイズ不一致、または期限超過と判定されたスロットは削除されます。フォルダー上限を超えると最終利用時刻の古い会話から削除します。エンジン終了時には RAM 内に残るスロットもフォルダーへ書き出します。

サーバー側の設定は子プロセス起動時に環境として渡されます。サーバーは `child_env()` をエンジン起動の `env` に指定します。直接起動ではサーバー側の既定値補完は行われません。

## 文書との照合

`docs/DEEPSEEK41.md` は `STRATA_DS4_SLOT_KEEP=0` で無効化でき、会話が再起動後にも戻ることを説明しており、コードと一致します。同資料にある 2 GB のフォルダー上限はサーバー既定値です。エンジンを直接起動した場合のソース既定値は 16 GiB相当で、サーバー経由の場合は `serve/server.py` が 2 GB を設定します。
