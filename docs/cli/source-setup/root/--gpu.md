# `--gpu`

調査対象: Strata commit `7dd5cf18e68c639a8773e096c5c79f971ea2a9f5`（2026-10-25 時点）。

| 項目 | 内容 |
| --- | --- |
| ツール ID | `source-setup` |
| コマンド | `setup.py`（`setup.sh`、`START-HERE.bat`、`update.sh`、`UPDATE.bat` が引数を委譲） |
| オプション | `--gpu` |
| 別名 | なし |
| 値 | GPU 番号。通常は1枚を選択。カンマ区切り値は `--gpus` 相当として処理される |

## 役割

GPU 番号を指定して setup 対象または起動に使うカードを選びます。NVIDIA の番号は `nvidia-smi` の番号、AMD の番号は setup が列挙する番号です。モデルを setup すると選択がモデル設定に保存されます。インストール済みモデルの通常起動時に指定した場合は、その起動だけで使う GPU の上書きです（`setup.py:8461-8462,8647-8650,9637-9639`）。

## 使い方

```sh
./setup.sh --setup --gpu 1
```

既存モデルをこの起動だけ GPU 1 で動かす場合は次のようにします。

```sh
./setup.sh --gpu 1
```

Windows では同じ `setup.py` parser に `START-HERE.bat --setup --gpu 1` のように渡します。POSIX wrapper は `setup.py "$@"`、Windows wrapper は `setup.py %*` として起動し、更新 wrapper も引数を渡す旨を明記しています（`setup.sh:6-12,76`、`START-HERE.bat:44-54`、`update.sh:5-6`、`UPDATE.bat:2-6`）。

## 値と既定値

parser は値を文字列として受け、`type`、`choices`、明示的な `default` は指定していません。値は省略できず、通常の値は GPU 番号です。番号の字句検査では前後の空白を許し、数字だけなら整数に変換します。空文字、負数、`all` など数字以外の単一値は `ap.error()` になります（`setup.py:8461-8462,8571-8577`）。

カンマが含まれる値は `--gpu` から `--gpus` へ移し、後段の複数 GPU parser に渡します。そのため `--gpu 0,2` は複数 GPU 選択として動きます。`--gpu` の help 表示は「one GPU」と説明していますが、この互換処理が実装されています。`--gpu all` はカンマを含まず単一値検査に失敗します。カンマ区切り値の個数・重複・整数形式は `parse_gpus()` が検査し、1枚だけ、重複番号、整数でない項目は失敗します（`setup.py:8571-8577,1660-1674`）。

番号自体が実在し、対象 backend で利用可能かどうかは、字句検査ではなく後続の GPU 検出・選択で確認します。通常の NVIDIA setup では `choose_gpus()` が指定番号を `check_gpus()` に渡します。AMD setup では利用可能なカード一覧から番号を探し、対象が見つからないか利用不可なら候補を示して停止します（`setup.py:1774-1783,8751-8758,8792-8799`）。

省略時の選択は経路によって異なります。NVIDIA では対応 GPU が1枚ならそれを選び、複数カードが同一モデルを共有できる場合は選択を尋ねます。AMD では対応 GPU のうち、専用メモリを持つカードを優先し、その後メモリ量で順位付けしたカードを選びます（`setup.py:1774-1791,3840-3843,8759-8766`）。

## 実行時の動作と相互作用

- setup で `--gpu N` を指定すると、選択 GPU は後続のモデル適合判定・engine 準備へ進みます。設定保存時、GPU が複数検出された場合または明示選択がある場合は `gpu` と `gpus_asked: true` を記録し、次回起動で同じ選択を尋ねないようにします（`setup.py:8792-8804,9637-9639`）。
- インストール済みモデルの通常起動では `a.gpu` が起動用 GPU として渡されます。明示しない場合は保存済みの選択が使われ、`--gpu` を付けてもその起動だけの指定です（`setup.py:8606-8609,8647-8650,8677-8682`）。
- `--gpus` と併用して `--gpu` にカンマ区切り値を渡した場合、既に `--gpus` があればそれを優先し、`--gpu` の値は `--gpus` に移しません（`setup.py:8571-8575`）。`--gpu-roles` も併用できず、GPU 選択後に parser error になります（`setup.py:8578-8581`）。
- AMD の複数 GPU 共有は Windows では拒否されます。NVIDIA と AMD の両方が使える環境で `--backend` を省略したときは backend 選択を尋ねる経路があります。AMD で `--gpu` を使う場合は AMD の列挙番号で指定します（`setup.py:8708-8729,8731-8733,8751-8758`）。
- `--backend sycl` は共通 parser 後に `sycl_setup()` へ委譲されます。SYCL 専用 setup での GPU 選択の詳細はこのオプション文書では追跡していません（`setup.py:8548-8552,8561-8564`）。

setup は GPU の検出と利用可否判定を行い、モデル設定にカード番号を書き込みます。実際の engine が起動するデバイスは、その後の engine・driver・実機の状態にも依存するため、この指定だけで起動成功までは保証されません。

## 出力と失敗経路

字句が不正な値や `--gpu-roles` との併用は `argparse` の `ap.error()` になり、usage とエラーを表示して終了します（`setup.py:8571-8581`）。番号が実機にない、または GPU が backend で使えない場合は setup の `fail()` が診断と候補を出し、終了コード 1 で停止します（`setup.py:825-830,1681-1703,8754-8758`）。カンマ区切り値の形式エラーも `parse_gpus()` の `fail()` 経由で終了コード 1 です（`setup.py:1660-1674`）。

選んだ GPU によって対応 engine がない場合の詳細な engine 選択・構築結果は CUDA 世代、backend、実機などに依存します。本調査では全 platform/backend の実機で確認していません。
