# `--no-start`

調査対象: Strata commit `7dd5cf18e68c639a8773e096c5c79f971ea2a9f5`（2026-10-25 時点）。

| 項目 | 内容 |
| --- | --- |
| ツール ID | `source-setup` |
| コマンド | `setup.py`（`setup.sh`、`START-HERE.bat` などからも利用） |
| オプション | `--no-start` |
| 別名 | なし |
| 値 | 取らない真偽フラグ |

## 役割

モデルのセットアップを行い、設定と起動スクリプトを用意した後、モデルサーバーを起動せずに終了します。dry-run ではありません。モデルやエンジンなどの取得・ビルド、設定ファイルの書き込みは通常どおり行われ得ます。

## 使い方

Strata リポジトリのルートで実行します。

```sh
./setup.sh --model IQ2_XS --yes --no-start
```

Windows では `START-HERE.bat --model IQ2_XS --yes --no-start` のように指定できます。POSIX ラッパーは全引数を `setup.py` に渡し、Windows ラッパーも Python 起動時に引数を渡します（`setup.sh:6-12,76`、`START-HERE.bat:8-10,44-54`）。

## 値と既定値

値は不要です。`argparse` の `store_true` で宣言されており、省略時は `False`、指定時は `True` です。同じフラグを複数回指定しても真のままです。別名や値の範囲はありません（`setup.py:8493-8496`）。

このオプション固有の追加 validation はありません。別の位置引数を受け取る定義もなく、値を付ける形式は parser で拒否されます。ほかのオプションの validation やセットアップ失敗は通常どおり適用されます（parser と処理分岐: `setup.py:8420-8427,8493-8496,8553-8556`）。

## 実行時の動作

通常のセットアップでは選択・取得・構成処理を続け、設定ファイルと起動スクリプトを書き出し、「All set.」や API の接続先などを表示した後、終了コード `0` で戻ります。通常起動の `start(...)` 呼び出しには進みません（標準経路: `setup.py:9712-9730,9738-9766`）。

Qwen3.6 系の own-path と DeepSeek-V4.1 のセットアップ経路でも、設定・起動スクリプトを作成して完了表示を出した後に `0` を返します（`setup.py:7717-7732,8146-8158`）。Apple Silicon の Metal 用セットアップにも同じフラグがあり、設定と起動スクリプトの作成後にモデル起動を省略します（`metal/setup_mac.py:327-356,547-558`）。

ただし、オプションの作用は「起動だけを省く」範囲です。既存モデルがある状態で `--no-start` を指定すると、単純な既存モデル起動の条件から外れ、明示的なセットアップ要求として扱われます。モデル設定変更や追加セットアップの経路へ進むため、既存インストールを変更せずに保つ指定ではありません（`setup.py:8602-8622,8677-8695`）。

## 適用条件と副作用

- 標準経路では `--no-start` により、インストール後の任意の tuning 提案と quick benchmark 提案もスキップします。ただし、明示的な `--calibrate` による既存モデルの較正経路は別で、較正を実行した後にモデルを起動せず戻ります（`setup.py:8652-8676,9731-9766`）。
- フラグ指定時も setup の処理は実行されるため、モデルファイル取得、エンジン取得・ビルド、設定ファイルや起動スクリプトの書き込みが起こり得ます。`--no-start` が直接止めるのは `start(...)` への進行です（`setup.py:7717-7732,8146-8158,9729-9766`）。
- `--check` は後段のチェック専用分岐で終了します。`--no-start` を付けても通常インストールには進まず、適合判定に応じた終了コードになります（`setup.py:8620-8622,8860-8909`）。
- `--update` は `--no-start` を含むセットアップ判定より前に処理され、もともとモデルを起動しない更新処理を実行します。`--rollback-engine` もそれ以前に処理されます。これらの組み合わせで `--no-start` が追加する動作はありません（`setup.py:8614-8620`）。
- `--inspect` は parser 後、通常のセットアップ分岐より先に検査ツールを実行して終了します（`setup.py:8553-8564`）。
- POSIX `setup.sh` と Windows `START-HERE.bat` は引数を委譲します。`SETUP.bat` は `--setup` を追加し、`update.sh` と `UPDATE.bat` は `--update` を追加して委譲します（`setup.sh:6-12,76`、`START-HERE.bat:44-54`、`SETUP.bat:1-3`、`update.sh:62-64`、`UPDATE.bat:79-81`）。

## 出力とエラー

成功時はセットアップ完了と起動スクリプト名などが表示され、モデルは起動せず `0` を返します。通常セットアップ中の検出・取得・書き込みエラーはこのフラグで抑止されず、その経路のエラー処理に従います。特定のエラー文言や終了コードは失敗箇所に依存し、`--no-start` 専用の失敗経路は parser に定義されていません。
