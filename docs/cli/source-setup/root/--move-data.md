## 役割

`--data-dir` で現在の保存先とは別のデータフォルダーを指定したとき、Strata がこの PC 上の既存モデルファイルを新しいフォルダーへ移す選択を明示します。モデルファイルの通常の保存先を変更するだけの `--data-dir` と異なり、このフラグを付けると、同一ドライブ上の既存データを新しい場所へ移す処理が有効になります。

## 使い方

Linux で setup を行い、新しい保存先へ既存のモデルも移す例です。Windows では `START-HERE.bat` に同じ引数を渡せます。

```sh
./setup.sh --setup --data-dir "$HOME/Strata-data-new" --move-data
```

この例は既存のモデルファイルを移動します。移動を望まない場合は `--move-data` を付けずに実行します。

## 値と既定値

- `setup.py` の parser は `action="store_true"` として登録し、値を受け取りません。省略時は偽です。重複指定しても真のままです（`setup.py:8481-8485`）。
- このフラグ単体では移動先を指定しません。新しい場所は `--data-dir DIR` で指定します。
- `--move-data` がなく、移動可能な既存データがある状態で、新しい `--data-dir` を指定して `--yes` も付けない場合、対話実行では `keep` / `move` を尋ね、既定の回答は `keep` です。`--yes` の場合は移動の質問をせず、既存データを残します（`setup.py:6074-6096`）。

## 実行時の動作

`data_folder_for()` は `--data-dir`、`--move-data`、`--yes`、`--set-default-data-dir` を `data_folder()` に渡します（`setup.py:6136-6139`）。`setup.py` の通常起動では、既存モデルの単純起動以外にこの関数が呼ばれ、setup・確認・更新などの経路でデータフォルダーを解決します（`setup.py:8602-8610`）。既存モデルの単純起動では `data_folder_in_place()` が使われるため、`--move-data` だけを付けても移動処理には入りません（`setup.py:8602-8610,6142-6151`）。macOS の通常 CLI は `metal/setup_mac.py` に引数解析を委譲し、同ファイルも `--move-data` を同じ属性名で受け取り、`setup.py` の `data_folder_for()` を呼びます（`setup.py:8418-8420`、`metal/setup_mac.py:327-344,365`）。Linux/Windows wrapper は引数を `setup.py` へそのまま渡します（`setup.sh:6-12,76`、`START-HERE.bat:48,53`）。

新しい `--data-dir` が記憶済みフォルダーと異なる場合、Strata はこのインストール、過去の Strata インストール、記憶済みフォルダーなどにモデルデータがあるかを調べます。既存データがなければ移動対象はなく、新しい場所が既定の保存先になります（`setup.py:6067-6098`）。対象データがあり、`--move-data` が指定されていれば `move` の質問を飛ばし、移動処理へ進みます。指定がなければ `--yes` は「既存データを残す」側を選び、通常実行では質問への回答で選択します（`setup.py:6081-6098`）。

移動処理は同一ドライブのデータに限られます。モデル (`models`) はファイル単位で統合し、移動先に同名のファイルがあれば移動先のものを保持します。pack と MTP データは移動先に同じ項目がない場合に移します。実装は同一ドライブ上で `atomic.replace()` による rename を試み、失敗時はディレクトリーを再帰的に統合します。使用中など移動できない項目は元に残ります（`setup.py:5965-5991,6105-6129`）。移動後、移動元にある `strata-*.json` のうち共有設定ファイルでないモデル設定を調べ、移動先にファイルが存在し元のパスにはない値だけを新しいパスへ更新します（`setup.py:5993-6018,6366-6369,6123-6129`）。

移動が選択されると、最終的に `settings.json` の `data_dir` と対象インストール一覧も保存されます。`--set-default-data-dir` は既存データを残して早期終了する場合にも新しい保存先を記憶します。`--data-dir` なしではこのフラグによる移動選択分岐には入りません。`data_folder_for()` を通る setup・確認・更新の経路では、フラグの有無に関係なく通常のデータフォルダー整理として記憶済み保存先へ同一ドライブ上のデータを集めますが、既存モデルの単純起動ではその整理も行われません（`setup.py:6074-6098,6105-6133,8602-8610,6142-6151`）。

## 適用条件と副作用

- 新しい `--data-dir` が現在の保存先と異なり、移動対象となる既存データがある場合に、`--move-data` が「移す」選択として作用します。同じ場所を指定した場合、別フォルダーへの移動を選択する分岐には入りません（`setup.py:6051-6053,6074-6079`）。
- 別ドライブにあるデータは移動されず、その場所に残って引き続き参照されます。同一ドライブかどうかは `st_dev` で判定されます（`setup.py:5965-5969,6081-6082,6105-6109`）。
- 移動先の検証に失敗した明示的な `--data-dir` は `fail()` で終了します。移動先ディレクトリーを作れない場合は警告し、このインストールフォルダーを保存先として使います（`setup.py:6054-6066`）。
- `move_into()` は移動できない項目を元に残す実装です。処理後にもデータが残れば警告し、元フォルダーを引き続き使う場所として返します。これはファイルのコピー完了を保証する処理ではありません（`setup.py:5972-5991,6123-6129`）。
- 保存設定の書き込みに失敗した場合は警告が出ます（`setup.py:5922-5929`）。

## 出力とエラー

- 移動しない場合は、既存モデルを元に残し、新規ダウンロードを新しいフォルダーに置く旨を標準出力へ表示します（`setup.py:6091-6096`）。
- 移動完了時は移動元と移動先を `[ok]` メッセージで表示します。移動できない、または移動先にも元にもファイルが残る場合は警告を表示します（`setup.py:6125-6129`）。
- 明示した移動先が利用不可の場合は理由と「変更もダウンロードもしていない」旨を表示して終了コード `1` で停止します。`fail()` は `sys.exit(1)` を使います（`setup.py:825-830,6054-6057`）。
