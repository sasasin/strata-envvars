# `--move-data`

調査対象: Strata commit `d46f5f268f8ed797e83a5c63a69bffbd7a581cf6`（`2026-11-24` 時点）。

| 項目 | 内容 |
| --- | --- |
| ツール ID | `source-setup` |
| コマンド | `setup.py`（`setup.sh` / `START-HERE.bat` から呼び出されるセットアップ） |
| オプション | `--move-data` |
| 別名 | なし |
| 値 | 値を取らない真偽値。指定すると有効（既定値 `False`） |

## 役割

`--data-dir DIR` で新しいデータフォルダを指定したとき、既存のモデルファイルをそのフォルダへ移す選択を明示する。モデルの保存先だけを変え、既存ファイルは元の場所に残す動作とは区別される。

## 使い方

Linux でセットアップを実行する例:

```sh
./setup.sh --setup --data-dir /mnt/strata-data --move-data
```

`--move-data` 単独では移動先を指定しない。移動先は `--data-dir` の値で決まる。`terminal/setup.py` が `--move-data` を `store_true` として登録し、`data_folder_for()` が値を `data_folder()` に渡す（`terminal/setup.py:11510-11516`, `7513-7516`）。

## 値と既定値

引数値・選択肢・数値範囲はない。指定がなければ `False`。同じ真偽値オプションを複数回書いた場合の特別な処理はなく、`argparse` の `store_true` として扱われる（`terminal/setup.py:11512-11514`）。

`--move-data` 自体の値検証はない。指定した移動先の妥当性は `--data-dir` 側で調べられ、指定先に問題がある場合は `fail()` で処理を止める（`terminal/setup.py:7430-7434`）。

## 実行時の動作

`data_folder()` は現在の設定に記録されたデータフォルダ、Strata の各インストール先、および関連する `Strata-data` を移動元候補として集める。`--data-dir` が現在使っているフォルダと異なる場合、`--move-data` が真なら移動確認をせず移動処理へ進む（`terminal/setup.py:7444-7459`）。

同じドライブ上の移動元では、`models` 以下のファイルを移動先へ統合し、`packs` 内の項目と `mtp` は移動先に同名の項目がない場合に移す。関連するモデル設定ファイルのパスも、移動元にファイルがなく移動先にある場合に更新する。移動先に同名のファイルがすでにある場合、コピー元で置き換える動作ではない（`terminal/setup.py:7349-7367`, `7370-7395`, `7482-7506`）。

移動処理が終わると、移動先を `settings.json` の `data_dir` として保存し、今回も使われている、または移動先にすでに同じデータがあるため残ったファイル群は元の場所で引き続き参照される。残存ファイルがあれば警告する（`terminal/setup.py:7502-7510`）。

## 適用条件と副作用

- `--data-dir` を指定しない場合、フラグだけで別の移動先は作られない。データフォルダ選択処理は通常の記憶済みフォルダを使い、`move` 引数が新しい指定先への移動判断に使われる分岐には入らない（`terminal/setup.py:7430`, `7451-7459`）。
- 移動元に既存データがある場合、`--move-data` を指定すれば、`--yes` の有無にかかわらず移動を選択する。`--yes` 単独は移動を意味せず、移動元をそのまま使い続ける。`--yes` がなく `--move-data` もない場合、同じドライブに移動可能なデータがあれば確認し、既定の `keep` は移動しない（`terminal/setup.py:7458-7473`, `1077-1092`）。
- 別ドライブ上のデータは移動対象にならず、その場所で引き続き使われる。移動処理は同じドライブかを確認してから実行する（`terminal/setup.py:7342-7346`, `7482-7486`）。
- `setup.py` の通常起動、セットアップ、チェック、更新など、データフォルダを解決する経路で参照される。既存モデルの単純な起動経路は `data_folder_in_place()` を選ぶ場合があり、単純起動でこのフラグだけを付けても移動指示にはならない（`terminal/setup.py:11681-11688`）。
- データフォルダやモデル設定ファイルを変更し、ファイル・ディレクトリを移動する副作用がある。`move_into()` は同一ドライブでの rename を試み、失敗時はディレクトリを再帰的に統合する。使用中などでファイルが残った場合は保持される（`terminal/setup.py:7349-7367`, `7500-7509`）。

同じ文字列の `strata launch --move-data` は別の parser scope であり、この文書の対象ではない。`strata launch` では選択結果を setup.py の引数に転送する実装もある（`terminal/strata_cli/launch/cmd.py:88-90`, `601-622`; `terminal/strata_cli/launch/runner.py:1399-1405`）。

## 出力とエラー

移動せず既存データを保持する経路では、元の場所にモデルが残る旨と新しいダウンロード先を表示する。対話式の確認では `keep` / `move` を受け付け、空入力は既定の `keep`、入力終了（EOF）はエラーとしてセットアップを終了する（`terminal/setup.py:7460-7473`, `1077-1092`）。

指定したデータフォルダに問題があれば「何もダウンロード・変更していない」旨を表示して終了コード 1 で停止する。設定ファイルの保存に失敗した場合は警告を出す（`terminal/setup.py:7431-7434`, `7299-7306`; `fail()` の終了処理は `1049-1056`）。移動途中の個別ファイルが使用中などで動かせない場合はそのファイルを元に残し、残存を警告する経路がある（`terminal/setup.py:7351-7367`, `7502-7506`）。

移動先ディレクトリの作成で `OSError` が起きた場合は警告し、`home()` を移動先として続行する（`terminal/setup.py:7439-7443`）。
