## 役割

セットアップ中の対話質問を省き、質問ごとの既定回答を使います。ただし、危険性を示す確認まで無条件に承認するオプションではありません。明示した設定がリスクを伴うときに、その設定選択を承認として扱う経路がありますが、明示的な選択がない場合は通常その確認の既定（多くは「いいえ」）で止まります（`setup.py:34-37`, `setup.py:851-865`, `setup.py:5851-5860`）。

## 使い方

モデルをセットアップして起動する例（リポジトリのルートで実行）：

```sh
./setup.sh --yes --family qwen --model IQ2_XS
```

Windows では `START-HERE.bat --yes --family qwen --model IQ2_XS` のように指定できます。セットアップだけで起動しない場合は `--no-start` も指定します。`--yes` 自体は起動を抑止せず、通常のセットアップ経路は最後にモデルを起動します（`setup.py:8493-8495`, `setup.sh:6-12,76`, `START-HERE.bat:48-54`）。

## 値と既定値

オプション parser は `argparse` の `action="store_true"` で、引数値はありません。したがって指定時は真、未指定時は偽です。受け付ける値の範囲・数値検証はありません（`setup.py:8493`）。

通常の質問 helper `ask()` は `yes` が真なら入力を表示・読み取りせず、その質問に渡された `default` を返します。未指定なら質問を表示し、Enter で同じ既定値を採用します。入力が EOF になった場合は `fail()` から終了コード 1 で停止し、対話端末での実行または `--yes` の指定を案内します（`setup.py:851-865`, `setup.py:825-830`）。

## 実行時の動作

- セットアップ時のモデル、コンテキスト、画像利用、KV cache など、質問形式で選ぶ値は各質問の既定回答になります。たとえば 262,144 を超える context で RoPE scaling が未指定なら `yarn`、context が 8K 超で KV が未指定なら `int8` が選ばれます（`setup.py:9078-9089`, `setup.py:9097-9107`）。
- GPU 選択など、既定値が選択肢の先頭・推奨値とは限らない質問もあります。複数のインストール済みモデルから選ぶ起動時の質問では先頭のモデルが選択されます（`setup.py:8677-8691`）。
- リスク確認は別扱いです。`confirm_risk()` は `--yes` と明示的な選択（例: `--model`、`--gpus`）の両方がある場合に承認として続行します。明示選択がない場合は `ask()` の既定回答を適用し、その回答が「いいえ」なら `fail()` で停止します。RAM 不足の paging 確認も、`--model` または `--low-ram off` が明示されている場合と、それ以外の場合で承認条件が異なります（`setup.py:5851-5879`, 呼び出し箇所 `setup.py:9043-9045`）。GPU の共有に関する確認でも、選んだカードが実行可能だが共有には VRAM が不足するというリスクは、カードを明示していればこの承認規則に従います（`setup.py:1677-1693`）。
- `--data-dir` で既存モデルのある場所とは別のフォルダーを指定した場合、同じドライブ上の既存モデルを移動するか確認する通常経路は、`--yes` では「そのまま残す」を選びます。既存ファイルの移動を明示する `--move-data` は別の指定です（`setup.py:6042-6050,6074-6096,6136-6139`）。
- 既存インストールを引き継いで新しい checkout を同じ設定にする経路では、コードが `a.yes = True` にします。この場合も質問は省略されます（`setup.py:8622-8645`）。
- Darwin では `setup.py` が共通 parser より先に `metal/setup_mac.py` へ引数を渡します。同 parser も `--yes` を `store_true` として受け、モデルと画像の質問に `S.ask(..., a.yes)` を渡します。未知の引数は警告して続行します（`setup.py:8412-8419`, `metal/setup_mac.py:327-358,387-405`）。`--backend sycl` も別 setup へ委譲されますが、共通 setup の `main()` を使う旨は委譲先に記載されています（`setup.py:7321-7344`, `sycl/setup_intel.py:1-8`）。

## 適用条件と副作用

`--yes` はセットアップ用質問と、既存モデルを起動する際の選択・確認の双方に渡されます。ビルドツールのインストール確認も通常の `ask()` を使うため、`--yes` なら既定の「はい」を選びます（`setup.py:5376-5411`）。一方、モデルのインストール・ビルド・ダウンロードなどを単独で実行させる機能ではなく、適用される処理は他の引数や環境条件で決まります。

セットアップが完了した後に任意で提示する PC チューニングと quick benchmark は、`--yes` の場合は質問自体を出さず起動しません。`--no-start` は別オプションで、指定しなければセットアップ成功後に起動処理へ進みます（`setup.py:9731-9766`, `setup.py:8493-8498`）。

## 出力とエラー

通常の質問は `--yes` 指定時には表示・入力されず、選択結果に応じたセットアップ進捗や警告は引き続き `say()` / `warn()` 経由で出力されます。承認されないリスク確認やその他のセットアップ失敗は `[X]` と理由・ヒントを出して終了コード 1 になります（`setup.py:808-830`, `setup.py:851-865`, `setup.py:5851-5860`）。

`--yes` 自体に専用の終了コードや成功メッセージはありません。これは他の validation や失敗条件を無効にしません。たとえば見つからない・利用できない GPU は `check_gpus()` が引き続き失敗させます（`setup.py:1677-1703`）。
