# `--yes`

調査対象: Strata commit `d46f5f268f8ed797e83a5c63a69bffbd7a581cf6`（2026-11-24 時点）。

| 項目 | 内容 |

| コマンド | `setup.py`（Linux は `./setup.sh`、Windows は `START-HERE.bat` 経由でも指定可能） |
| オプション | `--yes` |

## 役割

対話式セットアップで尋ねる選択に、それぞれの推奨回答（通常はプロンプトの既定値）を自動適用します。Python の parser は `store_true` として登録しています。Linux wrapper は引数を `setup.py` にそのまま渡し、Windows wrapper も `%*` で転送します（`terminal/setup.py:11524`、`setup.sh:14-17`、`START-HERE.bat:49-64`）。

これは「全ての危険確認を承認する」指定ではありません。セットアップが危険と判定する構成でも、`--model` や `--gpus` など該当する選択を明示した場合に限り、このフラグを同意として扱う経路があります。フラグだけでは停止するリスク判定もあります（`terminal/setup.py:7228-7237`）。

## 使い方

```sh
# 推奨回答で対話選択を進め、インストール後にモデルを起動しない
./setup.sh --yes --no-start

# Windows wrapper でも同じフラグを渡せる
START-HERE.bat --yes --no-start
```

## 値と既定値

- 値や引数を続けて指定しません。`--yes` の有無だけを parser が記録します。既定値は未指定（`False`）です（`terminal/setup.py:11524`）。
- `ask()` は `yes=True` のとき、プロンプトを表示せずに呼び出し元から渡された `default` を返します。未指定で対話入力が EOF になると、エラーとともに端末で実行するか `--yes` を指定するよう案内します（`terminal/setup.py:1074-1087`）。
- 推奨値は質問ごとに異なります。例えば長い context での RoPE 方式は `yarn`、KV cache 質問は `int8`、GPU 選択質問は一 GPU が既定です（`terminal/setup.py:12170-12179`、`12196-12203`、GPU 選択は `7133-7152`）。

## 実行時の動作

`a.yes` は複数の質問や分岐に渡されます。初回セットアップの質問、複数モデルからの選択、画像設定などで既定回答を採用し、リスク確認では後述の明示選択との組み合わせでのみ継続同意になります（例: `terminal/setup.py:2345`、`5992`、`11753-11773`、`12170-12203`）。

指定すると、通常は対話時に選択できる任意の大きな context、複数 GPU、リスクのあるモデル設定などを推奨値へ変更するわけではありません。コマンドラインで明示された選択は保持され、セットアップは警告を出したうえでリスクに応じた確認を行います。`--gpus` で名前を指定した GPU の VRAM 不足や、`--model` で明示したモデルの RAM 不足などは、該当する `explicit` 判定と `--yes` がそろうと続行します（`terminal/setup.py:2345`、`7228-7237`、`7240-7255`）。一方、`--yes` だけで明示選択がない場合は、既定で拒否されるリスク確認を自動承認せず、停止します。

このフラグはセットアップ以外の実行モードでも使われます。既存モデルの通常起動では GPU やモデル選択などの問い合わせに使われ、復元済みの以前の設定を採用する経路では内部的に `a.yes = True` にされます（`terminal/setup.py:11700-11723`）。`--check` は PC と GPU の候補選択で `a.yes` 相当の既定選択を使います（`terminal/setup.py:11813`）。

指定時には一部の任意質問自体が省略されます。例として、長い context の KV 選択、追加チューニング、セットアップ直後のベンチマーク実行は `--yes` の場合に尋ねず、それぞれのコード上の既定動作になります（`terminal/setup.py:12196-12203`、`12528-12533`、`12555-12562`）。

## 適用条件と副作用

- `--yes` は質問への回答方針を変えるだけで、セットアップを読み取り専用にはしません。通常のインストール経路は環境確認後に依存物・engine・model 等を取得し、設定と起動用 script を書き込みます。インストール後に起動するかは `--no-start` など別条件で決まります（概要は `terminal/setup.py:1-22`、設定と script の生成は `12521-12527`、起動分岐は `12555-12562`）。
- 推奨回答の自動選択によって、通常は対話で止まる入力待ちがなくなります。明示値に危険がある場合も、警告・個別の制限・失敗条件は別途適用されます。例えば不在 GPU や利用不能な GPU は `check_gpus()` がエラーにし、`--yes` は一般的な強制上書きにはなりません（`terminal/setup.py:2246-2250`、`2345`）。
- `--yes` を付けても、RAM 不足など、暗黙の選択では止める規則を無条件に通過しません。例外経路と必要な明示指定は個々の確認箇所に依存します（`terminal/setup.py:7228-7237`、`7240-7255`、`11890-11925`）。

## 出力とエラー

`--yes` 自体について、専用の出力や終了コード変更はありません。質問が省略され、続行時は通常の進捗・警告が出ます。リスク確認が拒否扱いとなった場合、セットアップは理由と案内を表示して終了コード 1 で停止します（`terminal/setup.py:1044-1056`、`7228-7237`）。`ask()` を通る未指定入力が EOF になった場合も `fail()` により停止し、`--yes` または対話端末を案内します（`terminal/setup.py:1074-1087`）。
