## 役割

既に Metal 用の Strata 設定が見つかる Mac で、通常起動の代わりにセットアップ手順へ進ませます。セットアップではモデルなどを選び、必要なエンジン構築・モデル取得と準備を行い、実行設定と起動スクリプトを書きます。設定がまだない初回実行では `--setup` を省略しても同じセットアップ経路に進むため、このフラグの主な役目は既存環境でセットアップを再実行することです。

## 使い方

```sh
# 既存設定での通常起動ではなく、Mac のセットアップを再実行する
./setup.sh --setup

# 質問には既定の回答を使い、選択したモデルをセットアップして起動する
./setup.sh --setup --yes

# セットアップ後にサーバーを起動せず、設定と起動スクリプトを用意する
./setup.sh --setup --no-start
```

`setup.py` は通常モードの macOS では引数を `metal/setup_mac.py` に渡し、そこで `--setup` を `store_true` として解析します。例は Strata checkout のルートで実行する想定です。

## 値と既定値

- 値は不要で、指定すると真になります。省略時は偽です。重複指定しても真のままです（`argparse` の `store_true`）。
- 専用の値検証はありません。`--setup=true` のような文字列はこのフラグの値としては認識されず、未解析引数として警告されます。
- Mac parser は `parse_known_args` を使うため、未知の引数は parser エラーにせず `not used on a Mac: ...` と警告します。

## 実行時の動作

- macOS で通常の `setup.py` を実行すると、`setup.py` が Mac 用実装へ引数を転送します。Mac parser が既存の Metal 設定を列挙し、設定があっても `--setup` が指定されていれば通常起動の早期 return を通らず、Mac 検査・モデル選択などのセットアップへ進みます。初回で設定がない場合も同じセットアップ処理へ進みます。
- `--setup` 自体はモデルや設定内容を指定しません。モデルは別の `--model` または選択質問で決まり、他のセットアップ引数もそれぞれ独立して処理されます。`--yes` は質問で既定回答を使う指定、`--no-start` は完了後の起動を止める指定です。
- `--model` と `--build` も既存設定からの通常起動を抑止します。`--check` は Mac 検査の直後に結果を返して終わり、`--setup` と同時でもモデルの取得・準備には進みません。
- セットアップは必要なときに Metal エンジンをビルドし、モデルファイルをダウンロードまたは既存ファイルから検証し、準備済みモデルの pack 等を作ります。最後に `strata-<family/model>.json` の実行設定と `run-<model>.sh` を書き、`--no-start` がなければ設定を使ってサーバーを起動します。
- 実行設定は一時ファイルへ書いてから置換されるため、設定ファイルの更新は一括置換です。既存の同名設定は置き換わり得ます。モデルや準備データは指定されたデータ場所に作成・再利用されます。
- `--update` と併用した場合は更新分岐が先にモデル取得・準備の通常経路を抜けるため、`--setup` だけでモデルの再ダウンロードを強制するものではありません。

## 適用条件と副作用

- この文書の scope は索引で `metal/setup_mac.py` とされる Mac 用 CLI です。`setup.py` は macOS かつ Control モードでない場合に限り、この実装へ引き渡します。
- モデルの取得はネットワークを使い、エンジン・モデル準備ではビルドや大容量ファイルの作成が起こり得ます。`--setup` は dry-run ではありません。
- モデル準備のために再梱包または pack 作成が必要な場合、同じユーザーの Strata engine が稼働中なら、Mac をフリーズさせる危険を避けてセットアップを失敗させ、サーバーを止めて再実行するよう案内します。既に準備済みでその作業が不要な場合は、この特定の実行中 engine 判定には入りません。
- `--no-start` がなければ完了後にサーバープロセスを起動します。設定が参照する実行ファイルや GGUF が欠落している場合、起動前検査で失敗します。

## 出力とエラー

- セットアップ中は段階表示・状態表示を行い、未知引数があれば警告します。`--setup` 専用のエラー文や終了コードは定義されていません。
- Mac の適合性検査が失敗すると通常セットアップは失敗し、`--check` では問題の有無に応じて 1 または 0 を返します（これは別オプションの動作です）。モデル準備が必要なときに同一ユーザーの engine が動作している場合は、停止と再実行を促して失敗します。
- 完了後の終了値は、`--no-start` なら 0、起動する場合は起動した server subprocess の終了値です。
