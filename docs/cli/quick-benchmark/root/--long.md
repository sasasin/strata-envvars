# `--long`

調査対象: Strata commit `7dd5cf18e68c639a8773e096c5c79f971ea2a9f5`（2026-10-25 時点）。

| 項目 | 内容 |

| ツール ID | `quick-benchmark` |
| コマンド | `bench.sh` / `BENCH.bat`（委譲先: `python tools/strata_bench.py`） |
| オプション | `--long` |

| 値 | 値なしのフラグ。指定すると有効 |

## 役割

quick benchmark の通常項目に加え、約32,768トークンの入力プロンプトを使う「32K」テストを実行します。このフラグは長いテストを追加するもので、他のベンチマーク項目を省略しません。テストは標準ベンチマーク `strata bench run` とは別の簡易速度確認です（`tools/strata_bench.py:10-28`、`403-413`）。

## 使い方

リポジトリのルートで実行します。

```sh
./bench.sh --long
```

Windows では `BENCH.bat --long`、または委譲先を直接 `python tools/strata_bench.py --long` として実行できます。両 wrapper は引数をそのまま Python スクリプトに渡します（`bench.sh:6-10`、`BENCH.bat:8-18`）。

## 値と既定値

`argparse` では `action="store_true"` として定義されています。値を付けずに指定するフラグで、既定値は `False`、省略時は32Kテストを追加しません。値の型・範囲の検証はなく、同じフラグを複数回指定しても真偽値は `True` のままです（`tools/strata_bench.py:932-948`）。

## 実行時の動作

通常のウォームアップ、短いチャット、4K・16Kプロンプト、エージェントセッションを実行した後、`--long` が有効なら `run_prompt(32768, "32K")` を呼び出します。プロンプトは単語数を較正値から見積もって生成し、要求ごとに異なるタグを付けます。32Kテストは `--runs` の回数だけ新しいプロンプトで行われ、既定回数は3です（`tools/strata_bench.py:225-256`、`283-300`、`403-413`、`939-942`）。

このテストの生成上限は `LONG_MAX_TOKENS`、すなわち24トークンです。したがって `--long` が約32,768トークンにするのは入力プロンプトであり、生成する応答の上限ではありません（`tools/strata_bench.py:57-60`、`283-300`）。

## 適用条件と副作用

サーバーから context 長が取得でき、`32768 + 24 + 256` トークンを収容できないと判定された場合、32Kテストはスキップされ、その理由が `skipped` 結果とログに記録されます。context 長が未取得または偽値の場合、この条件ではスキップされずテスト要求が送られます（`tools/strata_bench.py:283-287`）。

追加の HTTP chat 要求をサーバーに送り、処理時間とモデル負荷が増えます。結果は既定の `bench/results`（または `--out` で指定した親ディレクトリ）配下の新しい結果フォルダーに `README.md` と `results.json` として保存されます。既存結果フォルダーと名前が重なる場合は別名のフォルダーが選ばれます。ベンチマークが起動したサーバーは終了時に停止されますが、既に動いていたサーバーはこのスクリプトから停止しません（`tools/strata_bench.py:777-782`、`910-918`、`1017-1018`、`1035-1037`）。

## 出力とエラー

テストが完了すると結果表とレポートの場所が表示され、JSON のパラメーターに `"long": true` と実行コマンドが記録されます。個々の要求が失敗した場合は `failures` に記録して処理を続け、スキップまたは失敗の件数を表示します。最終終了コードは要求失敗と他の主要測定結果の有無で決まり、32Kテストの失敗だけで常に非ゼロになるとは限りません（`tools/strata_bench.py:238-240`、`1011-1022`、`1034`）。
