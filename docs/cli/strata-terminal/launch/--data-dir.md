# `--data-dir`

調査対象: Strata commit `7dd5cf18e68c639a8773e096c5c79f971ea2a9f5`（2026-10-25 時点）。

| 項目 | 内容 |
| --- | --- |
| ツール ID | `strata-terminal` |
| コマンド | `strata launch` |
| オプション | `--data-dir DIR` |
| 別名 | なし |
| 値 | モデル関連ファイルを置くディレクトリのパス |

## 役割

モデルのダウンロード先となるデータディレクトリを指定します。モデルや補助ファイルの準備先を変えるほか、指定したフォルダーは以降の Strata 起動で使うデータフォルダーとして記憶されます。既存 preset を指定した場合も、このオプションの値が preset の `data_dir` に上書きされます。

## 使い方

```sh
strata launch --model q2_0 --data-dir ~/strata-models --no-tui
```

`DIR` はフルパスで指定します。空白を含むパスはシェルで引用符で囲んでください。

## 値と既定値

- 値は `DIR` の一つです。CLI 自体には型変換や選択肢の列挙はありません。
- 指定を省略すると `LaunchSettings.data_dir` は未指定のままです。起動処理は、既存モデルの run config が示す場所、Strata アプリ側の場所、または Strata の既定データフォルダーを使います。CLI parser の説明では既定値を「Strata's data folder」としています。
- 指定値は `folders.problem()` で検査されます。空白だけの値は空値扱いとなり、設定に適用されません。相対パス、Windows で不正な文字を含むパス、システムフォルダー、ディレクトリではない既存パス、書き込めない場所、親ディレクトリを作成できない場所などは拒否されます。`~` はホームディレクトリに展開して絶対パスかどうかを判定します。
- 同じ引数を複数回書いた場合に値をどう選ぶかを独自に処理するコードは見つかりませんでした。標準 `argparse` による解析です。

## 実行時の動作

parser は `--data-dir DIR` を `strata launch` の「what to run」グループに登録しています。設定作成時に既存 preset（あれば）を読み込み、その後この値が truthy なら妥当性を検査して `LaunchSettings.data_dir` に設定します。したがって preset に保存された場所より CLI の指定が優先されます。

モデル準備時、Terminal は選択した場所を `setup.py --data-dir DIR` として子プロセスへ渡します。さらに選択場所を `--set-default-data-dir` として渡すため、setup は既定データ場所として記憶します。起動設定を保存する preset でも、この `data_dir` が保持されます。すでに別の場所にモデルがある場合、既存ファイルは自動的には移動しません。対話実行で同じドライブ上に移動可能なモデルがあると確認を表示し、移動を選ぶか `--move-data` を指定したときに移動します。`--yes`、`--plan`、JSON 出力、または入力できない実行では既存ライブラリをそのまま残し、指定先を新しいダウンロード先として扱います。

## 適用条件と副作用

- 値の検査は `settings_from_args()` で行われ、指定先の存在しない末端部分があっても、最寄りの既存親ディレクトリが書き込み可能なら受理されます。ディレクトリ自体の作成は後続の setup 処理です。
- 書き込み可能性検査は、指定先が存在すればその中に、存在しなければ最寄りの既存親に一時ファイルを作って削除します。削除に失敗した場合の例外は握りつぶされるため、一時ファイルが残る可能性があります。
- setup は選択先を作成し、モデル・pack・MTP などを配置します。既存モデルの移動を選んだ場合はファイル移動、run config のパス更新、設定保存も行います。移動対象が別ドライブにある場合は移動せず元の場所に残ります。
- `--model-path` と併用した場合、モデル本体のファイルは `--model-path` 側を使い、`--data-dir` は準備済み pack や追加データの場所としても使われます。既存 run config が指定先と異なる場所のファイルを参照していると、その config を再利用せず、指定されたフォルダーで setup を行います。
- `--plan` はモデル・ダウンロード計画を表示し、移動確認や setup を行いません。ただし事前のパス検査では上記の一時書き込み確認が行われます。

## 出力とエラー

パスが拒否された場合、`settings_from_args()` は `ValueError` を送出します。`run_launch()` が通常出力では `strata: ...` を stderr に表示し、終了コード `2` を返します。`--output json` ではエラーを JSON として stdout に出し、同じくコード `2` を返します。パス検査の案内には、何もダウンロードまたは変更していない旨と代替パスの案内が含まれます。

setup 側で指定先を作成できない場合は警告して既定場所へ切り替える処理がありますが、Terminal からは `--yes` も渡されるため、この分岐で対話確認はしません。setup の失敗時は Terminal が setup の出力を読み、`LaunchError` として表示します。
