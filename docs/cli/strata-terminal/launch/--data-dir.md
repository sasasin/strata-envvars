# `--data-dir`

調査対象: Strata commit `d46f5f268f8ed797e83a5c63a69bffbd7a581cf6`（2026-11-25 調査）。

| 項目 | 内容 |
| --- | --- |
| ツール ID | `strata-terminal` |
| コマンド | `strata launch` |
| オプション | `--data-dir` |
| 別名 | なし |
| 値 | `DIR`（モデルファイルの保存先ディレクトリ。絶対パス） |

## 役割

モデルのダウンロード先として使うデータフォルダーを指定する。指定先はモデルのほか、準備済み pack や draft layer などの関連ファイルを置く場所にも使われる。コマンドラインで選んだフォルダーは起動時の設定にも記録され、次回起動や Strata アプリで共有される。既存モデルを移すかどうかは別の判断であり、このオプションだけでは移動しない。

## 使い方

```sh
# モデルの保存先を指定して起動する
strata launch --model iq3_xxs --data-dir /mnt/models/Strata-data
```

## 値と既定値

- 値は引数として受け取り、短縮別名はない。
- 指定値は `folders.problem()` で検査される。空白を除いた空値は既定扱いとなる。非空値は絶対パスである必要があり、Windows で使えない文字、システム用フォルダー、ファイルを指すパス、書き込み不能な既存フォルダー、または作成できないパスは拒否される。存在するフォルダーでは小さな検査ファイルを作成して削除し、未作成のパスでは最寄りの既存親フォルダーで書き込み可能性を確かめる。
- 省略時は preset の `data_dir` があればその値が使われる。preset にも明示値がなければ、既存モデルの保存場所、アプリまたは Terminal の記憶済みデータフォルダーなどを調べる。どれも該当しない場合は setup 側の既定フォルダーを使うため、常に単一の固定パスになるわけではない。
- 同じ `strata launch` 呼び出しで `--data-dir` を指定すると preset の保存先を上書きする。空文字は `settings_from_args()` の真偽判定を通らず、新しい指定として適用されない。

## 実行時の動作

parser は `DIR` を文字列として受け取り、`settings_from_args()` がフォルダー検査を行って `LaunchSettings.data_dir` に設定する。Runner は明示値を setup subprocess の `--data-dir` に転送する。明示値の場合はさらに `--set-default-data-dir` も渡すため、保存先を記憶して次回起動やアプリとの共有に使う。モデル・ダウンロード計画での必要容量や保存先表示にもこの値が使われる。

既存モデルがほかのフォルダーにある場合、`--data-dir` だけでは移さない。対話可能な通常実行では移動するか尋ね、既定の回答は保持（移動しない）。`--move-data` を付けると移動を選ぶ。`--yes`、`--plan`、`--output json`、またはキーボード入力がない実行では質問せず移動しない。移動しない場合、既存モデルは元の場所から引き続き使い、新しい保存先は新しいダウンロードに使われる。`--plan` は変更を行わない。

setup の移動処理は同一ドライブ上のモデル、pack、MTP 関連ファイルを対象にする。別ドライブ上のファイルはコピーせず元の場所で利用する。モデルファイルが複数の場所にある場合など、個別ファイルが残るケースでは警告を出す。

## 適用条件と副作用

- `--model-path` で利用者自身のモデルファイルを指定した場合も、別途 `--data-dir` を指定すれば、準備ファイルの保存先として使われる。既存 pack や draft layer が指定先の外にあれば、元の場所から利用する旨を通知する。
- ディレクトリ検査は既存先またはその親に一時的な検査ファイルを作成して削除する。実際のディレクトリ作成、データ移動、設定保存は後段の setup 処理で行われる。
- 明示した保存先は `--move-data` がなくても既定の保存先として記録される。移動を選ばず `--set-default-data-dir` が渡るケースも同様に記憶される。
- `--plan` では保存先を含む計画とディスク空き容量を確認するが、データは移動せず設定も変更しない。

## 出力とエラー

- パスが無効な場合は `ValueError` として扱われ、通常出力では `strata: ...` を stderr に表示して終了コード 2 となる。`--output json` では `ok: false` とエラー情報を含む JSON を出力する。
- 確認できた拒否条件は、絶対パスでない、システム用の場所、ファイルを指定、書き込み不可、親ディレクトリも作成不能、Windows の不正なパス文字など。拒否メッセージは代替場所を案内し、ダウンロードや保存先変更をしていない旨を含む。
- setup が保存先を作成できない場合、setup 側は警告して home を使うフォールバック経路を持つ。個別の OS・ファイルシステムでどのエラーが起きるかは実行時依存で、ここでは網羅できない。
