# `--no-tui`

調査対象: Strata commit `d46f5f268f8ed797e83a5c63a69bffbd7a581cf6`（2026-11-25 時点）。

| 項目 | 内容 |
| --- | --- |
| ツール ID | `strata-terminal` |
| コマンド | `strata launch` |
| オプション | `--no-tui` |
| 別名 | なし |
| 値 | 取らないフラグ（指定時 `True`） |

## 役割

`strata launch` の対話画面を使わず、起動の進捗を通常の行出力で表示し、起動後に接続先を出力してコマンドを終了する。モデルやプリセットなどの起動条件は別の引数で指定する。サーバーはバックグラウンドサービスとして動き続けるため、このフラグはサーバーを停止するものではない。

## 使い方

```sh
# 既存のモデルファイルを使い、画面なしで起動する
strata launch --model-path /data/models/IQ3_XXS --no-tui
```

## 値と既定値

値を取らない `argparse` の `store_true` オプションで、既定値は `False`。同じオプションの重複指定による別の効果はない。値を続けて渡す構文ではない。

## 実行時の動作

parser はこのフラグを `strata launch` にだけ登録する。実行時に `--no-tui` が指定されると、TTY の入出力が揃っていても TUI の条件を満たさず、画面なしの経路へ進む。処理本体は runner を呼び、モデル・エンジン準備、設定保存、必要な調整、サーバー起動、アクセス設定を行う。進捗は通常の行として stdout に出力され、起動後は URL、必要に応じてマスクされた API キーなどを表示して終了する。サーバー自体はバックグラウンドで稼働する。

この指定だけで `--yes` が有効になるわけではない。たとえばエンジン更新やエンジン未導入時のモデル取得確認は runner が別に扱い、TTY がある場合は確認を尋ねることがある。既存サーバーと異なる設定で同じポートを使おうとした場合、画面なし経路では自動再起動せず拒否されるため、再起動するには `--restart` が必要。同じ設定ですでに稼働中なら再利用する。

`--plan` は計画表示後に終了し、サーバーを起動しない別の動作モード。`--output json` を指定すると機械可読 JSON が出力され、通常の進捗行は抑制される。`--open` を併用した場合は、起動成功後に明示的にブラウザーを開く。

## 適用条件と副作用

- 起動条件（例: `--model`, `--model-path`, `--preset`）を何も指定せず、画面も使えない条件では、選択を尋ねずエラー終了する（終了コード 2）。
- `--no-tui` は画面をなくす指定であり、確認をすべて省略する `--yes` とは異なる。非 TTY 時の確認応答は `_ask_yes` の実装に従う。
- `--data-dir` と併用しても、既存モデルを新しい場所へ移す確認は行わず、既存ライブラリをそのまま残す。移動するには `--move-data` を指定する。
- 通常起動と同様、モデルやエンジンの取得、実行設定・プロファイルの保存、サーバー起動などが発生し得る。画面を出さないこと自体はこれらの副作用を無効にしない。

## 出力とエラー

通常出力では `_printer` が runner のイベントを平文で表示する。TTY でない stdout ではモデル・エンジン・調整の進捗を原則 10% 刻みで間引き、サーバー起動中の同種メッセージも間隔を空ける。正常に起動すると接続 URL を表示してコマンドは 0 で終了するが、サービスは継続する。

失敗時は通常出力なら `strata: ...` を stderr に出し、該当するエラーコードを返す。`--output json` ではエラーオブジェクトを stdout に出す。具体的な失敗コードは失敗した処理により異なる。
