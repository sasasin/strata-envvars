## 役割

推論実行で生成するファイルの出力先ディレクトリを指定します。生成トークン ID、top-5 結果、任意の logits や中間テンソルがここに保存されます。

## 使い方

```sh
mkdir -p ./hy4-output
strata-hy4-metal --model SQ64.strata --engram Engram-Q8.strata --tokens ids.txt --out ./hy4-output --gen 32
```

出力先ディレクトリは実行前に作成してください。例の `--model`、`--engram`、`--tokens` は各自の入力ファイルに置き換えます。

## 値と既定値

- `--out` の次の argv 要素を文字列としてそのまま採用します。既定値は `.`（カレントディレクトリ）です。空文字列を含め、パスの形式・存在・書き込み可否を検証する処理はありません（`engine/src/hy4flash/metal/hy4_metal_main.cpp:1488-1511`）。
- 複数回指定すると後に解析された値が前の値を置き換えます（同ファイル `:1504-1511`）。
- 値を省略した場合の明示的なエラー処理はありません。parser の `nxt()` は次の argv を無条件に読み取る実装です（同ファイル `:1504-1511`）。不足時の具体的な実行結果はソースから保証できません。

## 実行時の動作

- parser で受け取った値を `Runner::dump_dir` に渡し、中間ダンプの保存先として使います（`engine/src/hy4flash/metal/hy4_metal_main.cpp:1720-1722`）。
- `--serve` 経路は `--out` を読み込んだ後にサーバー処理へ分岐して戻るため、このオプションはそこで使われません（同ファイル `:1635-1675`）。以下のファイル出力の説明は offline 推論経路に適用されます。
- 正常に prefill まで進んだ場合、`--dump` または `--save-logits` を指定すると `logits.npy` を保存します。`--dump` はさらに層ごとの中間テンソルを保存し、router の値や Layer 0 attention 関連の値も対象になります（同ファイル `:1801-1809`、`:1105-1126`、`:1159-1165`、`:808-813`）。
- 生成を行う分岐では、生成 ID を `gen_ids.txt` に保存します。比較実行の `--ab` 経路では初回の比較結果を `gen_ids_plain.txt` と `gen_ids_spec.txt` に保存します（同ファイル `:1923-1927`、`:1929-1943`、`:1972-1976`）。正常終了直前には `top5.txt` も出力します（同ファイル `:1978-1980`）。
- パスは `out_dir + "/" + ファイル名` として連結されます。ディレクトリを作成する処理は確認できません。相対パスはプロセスのカレントディレクトリ基準です。空文字列を渡すと `/logits.npy` などルート直下を指すパスになります。

## 適用条件と副作用

- 指定先に同名ファイルがあると、NPY 出力は `fopen(..., "wb")`、テキスト出力は `std::ofstream` の既定モードで開くため、既存内容を上書きします（同ファイル `:49-60`、`:1924-1927`、`:1942-1943`、`:1975-1980`）。再利用する出力先には注意してください。
- 指定ディレクトリが存在しない、または書き込めない場合、`save_npy_f32` は `fopen` 失敗時に何もせず戻り、書き込み結果も検査しません。テキスト出力ストリームについても open/write 成否を検査していません。そのため保存失敗が CLI の明示的なエラーになるとは限りません（同ファイル `:41-60`、`:1924-1927`、`:1942-1943`、`:1975-1980`）。
- `--load-only` でモデル読み込み後に終了する経路では、通常の推論結果ファイルを作る処理に到達しません（同ファイル `:1630-1636` の早期 return）。モデル読み込みや推論の途中でエラー終了した場合も、正常終了時の `top5.txt` 等は作られないことがあります。

## 出力とエラー

`--out` の値自体に対する validation error や出力先作成エラーの診断は見つかりませんでした。オプション値不足についても専用の usage/error 分岐はありません。引数解析で未知のフラグに遭遇すると `ERR unknown flag ...` を stdout、`unknown arg ...` を stderr に出し、終了コード `2` で終了しますが、これは `--out` 固有ではありません（`engine/src/hy4flash/metal/hy4_metal_main.cpp:1604-1608`）。保存処理の失敗時の終了コードは、確認した保存コードには規定されていません。
