# `STRATA_MOVE_ALWAYS_COPY`

調査対象: Strata `main` の HEAD `011c9e600a93bbc9fd451c563501b5831c32bbca`（2026-10-22 時点）。対象は Strata 所有ソース。外部ライブラリの動作は対象外。

## 役割

モデル保存先を移す Control 処理で、同じボリューム間でも rename せずコピー経路を使わせます。通常の同一ボリューム移動では空き容量を追加で必要としない rename 経路になるため、この変数を使うとコピー経路の検証に使えます。`strata models move` の計画・実行と、中断した移動を `--leave` で取り消す処理に影響します。

## 値と判定

| 値 | `same_drive()` の結果 | 動作 |
|---|---:|---|
| 未設定 | ボリュームを実測 | 同じなら rename、異なればコピー |
| 文字列が厳密に `1` | `False` | 同じボリュームでもコピー経路 |
| 空文字、`0`、`true`、`1 ` など | ボリュームを実測 | override しない |

値は Python の `os.environ.get(...) == "1"` で文字列全体を比較します。数値変換、trim、大文字小文字変換はありません。空文字は設定されていても有効値ではありません。

## 有効になる条件

変数は `strata_control.models_move.same_drive()` が呼ばれるモデルフォルダーの移動・復旧経路でだけ判定されます。別ボリュームの場合、変数が未設定または `1` 以外でも通常どおりコピーです。`--plan` でも計画に含まれる同一ボリューム判定と必要空き容量に反映されます。

## 実行時の詳細

`same_drive()` は呼び出しごとに環境を読み直し、結果を static cache しません。`plan()` は移動元・移動先の近傍パスについて `st_dev` を比較し、比較時の `OSError` も別ボリューム扱いにします。`STRATA_MOVE_ALWAYS_COPY=1` なら、この比較を行わず `False` を返します。

計画では同一ボリュームなら必要空き容量を 0、コピー扱いならモデル総量の 1.05 倍として、移動可能かを判定します。実行時の同一ボリューム経路は `os.replace()` による移動です。コピー経路は `.part` に書き、サイズと SHA-256 を確認してから配置し、元ファイルを削除します。ハードリンクされた重複ファイルにはリンクを試み、失敗時は検証付きコピーに fallback します。

中断した移動を `--leave` で戻す際にも `same_drive()` を再度使います。この変数が `1` なら、同じボリュームでも移動先から元フォルダーへの復元を検証付きコピーで行い、その後に移動先側を削除します。環境変数を変更しても、既に開始した `move()` 内では計画時に決まった `same_drive` 値がその処理の最後まで使われます。
