## 役割

CUDA ビルドに含まれる `nvfp4_decode_bench` が、ベンチマーク用の合成 expert weight bytes の代わりにファイルから実際の weight blob を読み込むための変数です。通常の `strata` エンジンが読む環境変数ではありません。対象実行ファイルは CUDA が有効な場合だけ CMake で定義されます。

## 値と判定

| 状態 | 動作 |
|---|---|
| 未設定 | 固定 seed `20261012` から作った合成 blob を使う。 |
| 設定済み | 値全体をファイルパスとして `fopen(path, "rb")` に渡す。数値変換、空白除去、部分文字列比較はしない。 |
| 空文字 | 設定済みとして扱い、空のパスを開こうとする。開けなければ `cannot open ` と stderr に出し、終了コード 2 で終了する。 |

ファイルからは、コマンドライン引数で選ばれた形式ペアの blob サイズ `L.bytes` 単位で最大 `G` 個を読みます。1個も完全な blob を読めない場合（空ファイル、ファイルが1 blob未満、読み取り失敗を含む）は `<path> holds no whole blob` を stderr に出し、終了コード 2 で終了します。末尾の不完全な blob は数えず、`ferror()` の個別確認もありません。ファイル形式や寸法のヘッダー検証も行いません。

完全な blob が `G` 個未満なら、すでに読んだ blob を先頭から繰り返して `G` 個分を埋めます。余分なデータは読みません。成功時は `blobs: <読めた数> real from <path> (cycled to <G>)` を標準出力に出します。ファイルを指定しても、activation 入力や反復回数などベンチマークの他の乱数・引数は変わりません。

## 有効になる条件

- `nvfp4_decode_bench` の実行時だけ参照されます。これは Strata の通常実行ファイルではなく、CUDA 有効時にビルドされるベンチマークです。
- blob のサイズと解釈は `gu_type` / `d_type` の CLI 引数で決まります。ファイルパスから形式を判別したり、ファイル内の形式と CLI 指定の一致を検査したりしません。
- ファイルを開けない、または完全な blob がない場合はベンチマーク処理を続けません。

## 実行時の詳細

環境変数は `main()` 内で合成 blob の初期化後、GPU メモリ確保とコピーの前に一度読みます。値は実行中に再評価されず、このコードから子プロセスへ渡されることもありません。設定ファイルを読む経路や別の環境変数による上書きはありません。

ファイル読み込みに成功すると、その blob 群を GPU にコピーし、`native_expert_grouped` を warm-up 後に反復実行します。したがって、この変数はベンチマークが測る weight bytes と出力 hash に影響し得ます。通常の生成処理・推論結果を変える設定ではありません。
