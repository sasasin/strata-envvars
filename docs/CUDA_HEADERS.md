## 役割

`sycl/tools/migrate.sh` で CUDA ヘッダーのディレクトリを指定します。このスクリプトは CUDA ソースから SYCL ポートを作り直す開発用ツールです。通常の Strata エンジンやサーバーの実行時設定ではありません。スクリプトはこのディレクトリをコンパイルデータベースの `-I` 引数と、`dpct` の `--cuda-include-path` 引数に渡します。

## 値と判定

| 環境変数の状態 | `hdr` の値 |
|---|---|
| 未設定 | `/cuda-headers/include` |
| 空文字 | `/cuda-headers/include` |
| 空でない値 | その文字列をそのまま使用 |

判定は Bash の `${CUDA_HEADERS:-/cuda-headers/include}` です。空白や数値としての妥当性などは検査せず、値の加工もありません。空白を含む値も後続の Python 引数および `dpct` 引数には一つの引数として渡されます。

## 有効になる条件

この値を使うのは `sycl/tools/migrate.sh` を実行したときだけです。既定値はスクリプトに固定されており、別の環境変数、CLI 引数、設定ファイルから選び直す処理はありません。スクリプトは `hdr` の存在確認やディレクトリ検証をしないため、指定先が不正な場合の結果は後続コマンドに委ねられます。

## 実行時の詳細

スクリプト開始時に一度値を展開し、後続処理に渡します。Python が作るコンパイルデータベースでは各翻訳単位のコンパイル引数に `-I<ヘッダーディレクトリ>` を含め、続く `dpct` にも `--cuda-include-path=<ヘッダーディレクトリ>` を指定します。したがって影響するのは CUDA から SYCL への移行処理とその生成物です。既にある Strata 実行ファイルや SYCL ポートの起動時には読み取られません。

Strata の資料によると、この開発ツール用コンテナには `get-cuda-headers.sh` が NVIDIA の pip wheel から取得した CUDA 12.8 ヘッダーを含めます。既定パス `/cuda-headers/include` はこのコンテナ配置に対応します。ここでは外部の `dpct` がヘッダーをどう解釈するかまでは扱いません。
