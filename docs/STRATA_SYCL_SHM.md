# `STRATA_SYCL_SHM`

調査対象: Strata `main` の HEAD `011c9e600a93bbc9fd451c563501b5831c32bbca`（2026-10-22 時点）。外部ライブラリの環境変数は対象外。

## 役割

SYCL エンジンを Docker コンテナ内で起動する `sycl/serve/strata-sycl.sh` が、ホストの `/dev/shm` をコンテナにもマウントするかを制御します。ホスト上で画像 embeddings を `/dev/shm` に書いた場合、コンテナ内のエンジンから同じパスで読めるようにする設定です。エンジン自身に渡す環境変数ではなく、起動ラッパーが読む設定です。

## 値と判定

| 値 | 判定 |
|---|---|
| 未設定 | `${STRATA_SYCL_SHM:-1}` により `1` として扱い、マウントを試みる |
| 空文字 | Bash の `:-` 展開により `1` として扱い、マウントを試みる |
| 文字列 `0` | マウントしない |
| その他の文字列（例: `1`, `false`, `00`） | `0` と完全一致しないため、マウントを試みる |

値の数値変換や trim、大文字小文字変換はありません。さらにホスト側に `/dev/shm` ディレクトリがある場合にだけ Docker の bind mount 引数 `-v /dev/shm:/dev/shm` が追加されます。値が `0` でも、またはディレクトリがない場合でも、スクリプトはその理由を個別にログ出力しません。

## 有効になる条件

この変数を読むのは `sycl/serve/strata-sycl.sh` です。したがって、SYCL 用 engine としてこのスクリプトを起動したときに適用されます。通常の CUDA/HIP engine の環境設定ではありません。

画像リクエストで embeddings ファイルが `/dev/shm` に置かれるのは、サーバー側で `/dev/shm` が書き込み可能で、空き容量が `2 * embeddings のバイト数 + 16 MiB` より大きい場合です。それ以外ではサーバーは encoder 側のディレクトリを使います。コンテナがホストの `/dev/shm` を共有しないと、ホスト上の `/dev/shm` に作ったファイルをコンテナ内のエンジンが同じパスで参照できません。

## 実行時の詳細

ラッパーは Docker 起動引数を組み立てる時点で変数を評価し、条件が真なら `/dev/shm` の bind mount を `docker run` に渡します。実行中に環境を変更しても、その起動済みコンテナには反映されません。スクリプト自身は `STRATA_SYCL_*` を engine 向け環境変数の転送対象から除いているため、この値はコンテナ内 engine へ転送されません。

`serve/server.py` は engine プロセス環境を作る際、親プロセス環境をコピーして設定ファイルの `env` 項目を上書きし、その環境で子プロセスを起動します。したがって、ラッパーをこのサーバー経由で起動する構成では、設定ファイルの `env` に `STRATA_SYCL_SHM` を指定してラッパーに渡すこともできます。

マウントを切った状態で画像 embeddings がホストの `/dev/shm` に作られる場合、Intel 用サーバーラッパーは最初の該当ケースで「`/dev/shm` に空きがない」旨のログを一度出し、コンテナの engine が画像を読めないことを説明します。この文言は容量不足だけでなく、ホスト `/dev/shm` 以外のパスになった場合にも出ます。マウントを切ること自体はこの関数の挙動を変えず、画像の一時ファイルを engine から見えるようにする共有を無効にします。
