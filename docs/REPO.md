## 役割

`REPO` は、Intel SYCL 開発用の `sycl/tools/build.sh` が Strata のチェックアウト位置を指定するために読む環境変数です。スクリプトはこのパスの `sycl` ディレクトリを CMake のソースとして使います。通常のセットアップ、サーバー、CUDA/HIP エンジンの実行時設定では読み取られません。

## 値と判定

スクリプトは Bash の `${REPO:-$(git rev-parse --show-toplevel)}` を使います。

| 環境変数の状態 | `repo` に使う値 |
|---|---|
| 未設定または空文字 | スクリプトを実行したときのカレントディレクトリから `git rev-parse --show-toplevel` で得る Git のトップレベル |
| 空でない値 | 値をそのまま使う |

空白の trim、絶対パス化、存在確認、Git リポジトリであることの検証はありません。空でない相対パスは呼び出し元のカレントディレクトリから解決されます。値は後続のシェル展開で引用符なしに使われるため、空白を含むパスは単語分割され、意図どおりに扱われないことがあります。

## 有効になる条件

`sycl/tools/build.sh` を実行した場合に限ります。主に `strata-sycl-dev` Docker イメージ内で SYCL エンジンを構築する手順です。`docs/INTEL.md` と `docs/INTEL_ARC.md` の例では、ホストからマウントしたチェックアウトのパスを `-e REPO=/work/$H` でコンテナに渡しています。

ただし `REPO` が空でないだけで常に CMake のソースパスとして使われるわけではありません。スクリプトは選択したパスから `BUILD_DIR`（未設定または空なら `$repo/build-sycl`）を決め、そこに `build.ninja` がない場合だけ `cmake -S $repo/sycl -B $b ...` を実行して構成します。既存の `build.ninja` があれば構成をスキップして、そのビルドディレクトリをビルドします。その場合も `$repo` は既定ビルドディレクトリの決定には使われますが、既存 CMake キャッシュ内のソース位置を `REPO` で置き換える処理はありません。

## 実行時の詳細

変数はスクリプト開始時に一度シェル展開され、ローカル変数 `repo` に入ります。実行中の環境変更を再読込する処理はありません。パスが不正な場合の専用エラー処理もなく、後続の `cmake` / `cmake --build` に進みます。スクリプトはビルド出力からエラー行などを表示し、最後に `BUILD EXIT <終了コード>` を出力します。

この変数がソースコード内で使われるのはこのスクリプトだけです。同名の `REPO` は `setup.py` や Python ツールにもありますが、それらは固定値またはスクリプト内の変数で、環境変数 `REPO` の読み取りではありません。
