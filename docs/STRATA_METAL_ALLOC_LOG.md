# `STRATA_METAL_ALLOC_LOG`

調査対象: Strata `main` の HEAD `296b59d2f73c8f04a805df29c2fa97655adace78`（2026-10-14 時点）。

## 役割

Metal デバイスランタイムが作成・登録した大きなバッファのサイズを stderr に記録します。Metal ランタイムの `alloc_log()` にだけ判定があり、CUDA/HIP/SYCL の共有実装で同名変数を読む箇所はありません。通常の CUDA/HIP ビルドには影響せず、macOS 専用の `metal/` プロジェクトで Metal デバイスランタイムが組み込まれた実行経路が対象です（`metal/CMakeLists.txt:1-9,16-18,49-60`）。

## 値と判定

| 値 | ログ判定 |
|---|---|
| 未設定 | 無効 |
| 空文字を含む、何らかの値が設定されている状態 | 有効 |

値の文字列、数値、先頭文字は検査しません。`getenv(...) != nullptr` の判定なので、`0`、`false`、空文字も有効です。`alloc_log()` の最初の呼び出しで判定を `static const bool` に保存します。その後プロセス内で環境を変更しても再評価されません。各呼び出しのサイズは、ログ出力の有無にかかわらず atomic な累計値に加算されます。ログ対象は `n >= 16u << 20`（16 MiB）の場合だけです。表示の `MB` と `GB` はそれぞれ `n / 1e6`、累計 `/ 1e9` による十進単位です。

## 有効になる条件

Metal runtime の割り当て・登録処理が成功して `alloc_log()` まで到達する必要があります。新規バッファの割り当てが失敗した場合は、その呼び出しからログも累計加算も行われません。通常の確保では、要求サイズが 0 のときランタイムが 1 byte に置き換えるため、ログ閾値には達しません。ホストメモリ登録では登録範囲を 16,384 byte 単位に切り上げたサイズが判定に使われます。

この変数はログを切り替えるだけで、確保・登録の成否やサイズを変更しません。コード上に子プロセスへの転送や CLI による上書きはありません。

## 実行時の詳細

`malloc_device_raw()` と `host_alloc_raw()` は `new_alloc()` を通り、Metal バッファ作成成功後に `device alloc` または `host alloc` として記録対象になります。`host_register()` は既存のホスト領域から NoCopy バッファを作成し、成功後に `host register` として記録します。ログ形式は `strata metal runtime: <種別> <サイズ> MB (total <累計> GB)` です。しきい値未満の呼び出しでは累計だけが進みます。解放処理には減算がないため、`total` は現在使用中のメモリ量ではなく、プロセス内でログ関数に渡された成功済み確保・登録サイズの累計です。大きな確保後に解放しても過去の累計値は減りません。
