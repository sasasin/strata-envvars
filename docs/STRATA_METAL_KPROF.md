# `STRATA_METAL_KPROF`

調査対象: Strata `main` の HEAD `296b59d2f73c8f04a805df29c2fa97655adace78`（`2026-10-14` 時点）。

## 役割

Metalエンジンのデコード用ウィンドウについて、指定したトークン数のウィンドウを使い、GPU上のdispatch時間をパイプラインと重みの役割ごとに測る診断用フック。通常の計算経路を選ぶ設定ではなく、計測の追加実行を行う。ソースコメントも「test tooling」としている。

## 値と判定

| 環境変数の状態・値 | 動作 |
|---|---|
| 未設定 | `kt` は `0`。通常のウィンドウ実行のみ。 |
| 空文字、数値に変換できない文字列 | `atoi` の結果は `0`。通常のウィンドウ実行のみ。 |
| 10進整数に変換できる文字列 | `atoi` が先頭の空白と符号を許容して読み取った整数を `kt` とする。たとえば `  +4tail` は `4` として扱う。 |
| `kt` が実際の `Tn` と一致 | headを含むキャッシュ済みウィンドウの処理回数を数える。条件を満たす20回目に計測を実行する（ただしストリーミング中は実行しない）。 |
| `kt` が実際の `Tn` と一致しない | カウンターは増えず、計測しない。 |

値は `std::atoi` で整数化され、範囲検証やクランプはない。文字列全体の一致判定ではなく、変換された整数とウィンドウ長との一致判定である。負数や0は、同じ `Tn` のウィンドウがなければ計測を起こさない。

## 有効になる条件

- Metalの `Window` 実装でのみ参照される。したがって、このコードから確認できる適用範囲はMetalエンジンであり、CUDA/HIP/SYCLの設定ではない。
- 通常のウィンドウ生成時ではなく、同じウィンドウ形状を再利用する `wcache_` のヒット経路で計測対象を数える。
- `head` が真であること、環境変数から得た `kt` がそのウィンドウの `Tn` と等しいことが必要。
- 20回目の条件成立時に `stream_` が偽でなければ計測しない。カウンターは `!stream_` 判定より先に20回目まで進むため、その時点でストリーミング中なら後の回で再試行されない。
- 変数が未設定または一致しない場合のログ・追加計測はない。

## 実行時の詳細

環境変数の値は、キャッシュヒット経路に初めて到達したときに関数ローカル `static const` として読み取られ、以後そのプロセス内ではキャッシュされる。この経路での最初の実行より後に環境を変更しても、`kt` には反映されない。別の `Window` インスタンスが作られても `seen` は関数ローカルstaticなので、カウントはプロセス内で共有される。

対象となる20回目の通常ウィンドウ実行の直後に、計測関数は同じdispatch列を使ってGPU計測を追加実行する。dispatchをパイプライン名と、該当する場合は重みの名前でグループ化し、各グループではdispatch間にbarrierを置く。全dispatch列と各グループをそれぞれ7回計測し、中央値をミリ秒で出力する。標準エラーには `strata metal kprof:` で始まる行が出て、ウィンドウ長、dispatch数、全体のGPU時間、グループ単独時間の合計、および各グループの時間・合計に対する割合・名前が表示される。

この計測は追加のGPU実行を伴い、グループはbarrierを入れた単独実行として測られる。したがって出力のグループ時間や割合は、元のdispatch列を通常実行した場合の個々のkernelの寄与をそのまま分解した値ではない。Strataの資料はこの設定を「per-kernel GPU times」と要約しているが、集計方法の詳細は実装に基づく上記のとおりである。
