# `STRATA_ADMIT_SHORT_FIRST`

調査対象: Strata `main` の HEAD `477ac13cbe8e582c20484871ce459d20d82df09d`（2026-10-17 時点）。

## 役割

Strata の Python `--batch` サーバーで、制御線（エンジンへプロンプトを送るための排他的な制御権）を待つ新規リクエストの順番を変えます。設定値以下の長さのプロンプトを、より長いプロンプトより先に受付対象にします。トークンの読み取りや計算内容は変えず、受付順だけを変えます。

この設定は `serve/server.py` のモジュール読み込み時に一度評価されます。サーバー起動後に環境変数を変更しても、値は再読込されません。Strata のエンジンプロセスへこの変数を設定・転送する処理は見つかりません。これはサーバープロセス側の設定です。

## 値と判定

`os.environ.get("STRATA_ADMIT_SHORT_FIRST") or 0` を Python の `int()` で変換し、その結果を `max(0, ...)` で 0 以上にします。変換で `ValueError` になった場合は 0 です。

| 環境変数の状態・値 | 結果 |
|---|---:|
| 未設定、空文字 | 0（無効） |
| `0`、負の整数 | 0（無効。負数は 0 に丸める） |
| 正の整数（例: `128`, `+128`, 前後に空白のある `128`） | 指定したトークン数をしきい値にする |
| `128.0`、`abc` など整数に変換できない値 | 0（`ValueError` を捕捉） |

値全体を `int()` が解釈します。小数表記や数字の後ろに付加文字がある文字列は無効です。Python の整数文字列変換が受け付ける符号や空白は使用できます。

## 有効になる条件

- `serve/server.py` のサーバープロセスで有効です。C++ エンジン単体の設定ではありません。
- 受付待ちの順番を決めるのは `_take_control(..., new=True)` の初回受付だけです。実行中リクエストが制御線を再取得するときの待ちや、BYIELD 後の再開には適用されません。
- 値が正でも、比較対象となる新規リクエストが待っていなければ順序に影響しません。
- 既定値 0 では並べ替えを行わず、従来どおり制御ロックを取った順で進みます。
- 長いプロンプトも、関連設定 `STRATA_ADMIT_MAX_WAIT_S` 以上待つと短い側として扱われます。これにより長いプロンプトが無期限に後回しになるのを防ぎます。`STRATA_ADMIT_MAX_WAIT_S` は別途同じモジュール読み込み時に評価され、既定は 30 秒です。0 以下を指定すると helper が `None` を返し、この呼び出し側はそれを `0.0` にするため、待ち時間条件は直ちに満たされます。

## 実行時の詳細

新規リクエストはプロンプト長、到着時刻、新規受付かどうかを待ち行列に登録します。制御線を取得できる番になったとき、設定が正なら `_admit_next()` が新規受付の待ち行列から次の候補を選びます。プロンプト長がしきい値以下、または `STRATA_ADMIT_MAX_WAIT_S` 以上待った候補を優先し、その候補群内では到着時刻の早いものを選びます。候補が制御ロックの取得を待っている間に短いリクエストが加わった場合も、ロック取得後に候補を再確認し、順序が変わっていればロックを譲ります。

判定対象の長さは `generate_batched()` が受け取った `ids` の要素数です。選択後は通常どおりプロンプトをエンジンに送り、同時に複数の `--batch` リクエストがある場合も、制御線を使う受付処理は一度に一つです。この環境変数専用のログ出力や警告は実装されていません。
