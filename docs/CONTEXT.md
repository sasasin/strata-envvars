# `CONTEXT`

調査対象: Strata `main` の HEAD `a0116b2782a5b82622358c04a06496485d12b2d6`（2026-10-13 時点）。

## 役割

Docker 用 `docker-entrypoint.sh` が、モデルの初回セットアップ時に `setup.py --context` へ渡すコンテキスト長（トークン数）を指定します。Strata のエンジンやサーバーが `CONTEXT` を直接読む箇所は確認できませんでした。Docker イメージ以外の起動経路で、この名前を設定として読むコードも確認できません。

## 値と判定

| 入力 | entrypoint / setup の処理 |
|---|---|
| 未設定または空文字 | シェルの `${CONTEXT:-32768}` により `32768` を `--context` に渡す。 |
| 整数文字列（例: `65536`） | `--context` の `argparse type=int` で整数に変換し、非ゼロならその値を採用する。選択肢リストにない整数も、`setup.py` のこの引数では選択肢による制限を受けない。 |
| 整数でない文字列 | `argparse` の整数変換でエラーとなり、セットアップに失敗する。 |
| `0` | `setup.py` は `if a.context:` で判定するため明示値として採用せず、コンテキスト選択へ進む。entrypoint は `--yes` を付けるので、GPU と RAM から求めた推奨値が選ばれる。 |
| 負の整数 | Python 側で正値チェックは見つからず、非ゼロなので明示値として後続処理に渡る。負値でのエンジン実行結果はこのコード調査では確認していない。 |

空文字は `:-` のため既定値扱いになります。数値の空白や符号などの細かな受理規則は Python の `int` 変換に従います。Docker entrypoint は文字列を数値検証せず、そのまま引数に渡します。

## 有効になる条件

- `CONFIG` が空でない場合はその設定ファイルを選び、`CONTEXT` を使ったセットアップを行いません。`CONFIG` の未設定と空文字は entrypoint 内で同じ扱いです。
- `CONFIG` がなく、`REINSTALL` が `1` でなく、モデル設定への既存シンボリックリンクが `/data/config/` 配下のファイルを指す場合も、そのリンクを保ってセットアップを省略します。
- 上記以外では、モデル設定ファイルがまだない場合、または `REINSTALL=1` の場合に `setup.py --setup --yes ... --context "$CONTEXT"` が実行されます。既存設定を変更するには `REINSTALL=1` が必要です。`REINSTALL` の比較は文字列の完全一致で、例えば `true` は `1` と同じ扱いではありません。
- `CONTEXT` はセットアップ時の設定値です。後続起動では entrypoint が `setup.py` を実行して保存済みの設定を起動するため、保存済み設定を使う経路では値を読み直しません。

## 実行時の詳細

コンテキストはモデルが一度に扱うテキスト量として説明され、セットアップは値に応じて設定を組み立てます。8192 以下では KV キャッシュを `fp16` にし、8192 を超えると既定の `int8`（または別途指定された KV 方式）を使います。65536 以上では RAM 量などの条件により KV streaming の設定も決まります。262144 を超える場合、Docker entrypoint が渡す `--yes` により追加質問は行わず、RoPE scaling は既定の `yarn` とコンテキスト長から導く係数になります。長いコンテキストが RAM 推定を超える IQ3_XXS / IQ3_S の場合、警告を出しつつ選択値を保持します。

セットアップが選んだ値は実行設定の `--max-context <値>` として保存されます。既存設定を使う後続起動ではこの値が使われます。Dockerfile は `CONTEXT` を entrypoint が読むセットアップ用環境変数として説明し、`docs/INSTALL.md` も `-e CONTEXT=32768` の例を示しています。
