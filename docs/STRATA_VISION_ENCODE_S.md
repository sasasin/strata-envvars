# `STRATA_VISION_ENCODE_S`

調査対象: Strata `main` の HEAD `a0116b2782a5b82622358c04a06496485d12b2d6`（2026-10-13 時点）。対象は Strata 所有ソース。外部ライブラリの環境変数動作は対象外。

## 役割

Python API サーバーが画像エンコーダーに画像の `ENC` コマンドを送った後、結果の1行を待つ最長時間（秒）を設定します。未設定または不正値なら300秒です。期限が切れるとサーバーはエンコーダープロセスを終了し、その画像処理をエラーにします。これは画像エンコーダーの起動時 `READY` 応答を待つ時間ではありません。起動時間は別の `STRATA_VISION_READY_S` が設定します。

## 値と判定

値は `float(os.environ.get(...))` で変換されます。`float()` が `ValueError` を出す値（空文字、数値でない文字列など）は既定値の300.0秒に戻ります。変換後が0以下なら `None` になり、`Queue.get(timeout=None)` に渡されるため待ち時間の上限を設けません。正の数値は秒単位の待ち時間として使われます。小数値も受け付けます。コードに有限値の検査はなく、NaNや無限大も明示的には拒否されません。

| 環境変数の状態・値 | サーバー側の値 |
|---|---|
| 未設定 | 300.0秒 |
| 空文字または `float()` で変換できない値 | 300.0秒 |
| `0`、`-1`、`-0.5` など0以下 | 上限なし |
| `0.25`、`30` など正の数値 | 指定秒数 |

判定は `serve/server.py:238-243,262-264` にあります。値を文字列として完全一致比較したり、範囲を上限で clamp したりする処理はありません。

## 有効になる条件

- 設定を読むのは `serve/server.py` のモジュール読み込み時です。サーバープロセス起動後に環境を書き換えても、この定数は再評価されません。
- `Vision` が構成され、画像をエンコードする経路で使われます。画像エンコーダーがない場合や、画像の読み込み・正規化で先に失敗する場合、この待機時間には到達しません。
- `Vision.encode()` はエンコード済み画像のキャッシュに当たるとすぐ返るため、エンコーダー応答待ち自体がありません。新しい画像のエンコードでは `ENC` を送信し、応答行の読み取りにこの値を使います。複数画像は1画像ずつ処理され、各画像の応答待ちに適用されます。
- CLI 引数やモデル設定ファイルによる同値の上書きは、この変数の読み取り箇所にはありません。起動待ちの `STRATA_VISION_READY_S` やエンジンの `STRATA_ENGINE_READY_S` とは別設定です。

## 実行時の詳細

`Vision.encode()` はロック内で `ENC <画像ファイル> <出力ファイル>` を標準入力へ書き、`_readline()` に `VISION_ENCODE_S` を渡して標準出力の1行を待ちます。読み取りは daemon thread で行い、指定秒数内に行が来なければエンコーダーを kill し、`the image could not be read: it said nothing for N s` という `RuntimeError` を発生させます。エンコード側はこれを `ValueError` にし、エンコーダーを停止状態としてマークします。画像の一時ファイルは `finally` で削除されます。後続のモデルロード経路は停止したエンコーダーを再起動します。正の小数の期限でも、エラー文中の秒数は `:.0f` で丸めて表示されます。

該当コード: `serve/server.py:2112-2132,2258-2272`。画像エンコーダーが起動時に `READY` を返さない場合は、別定数 `VISION_READY_S` と同じ読み取り処理を使います（`serve/server.py:2097-2110`）。
