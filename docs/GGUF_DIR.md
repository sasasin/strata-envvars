# `GGUF_DIR`

調査対象: Strata `main` の HEAD `a0116b2782a5b82622358c04a06496485d12b2d6`（2026-10-13 時点）。

## 役割

Docker コンテナの初回モデルセットアップで、既に用意した GGUF ファイルのフォルダーを指定します。値が空でなければ `docker-entrypoint.sh` が `setup.py --gguf-dir <値>` に変換し、セットアップはそのフォルダー内のモデル shard を使います。通常のモデルダウンロード先へ GGUF をコピーする指定ではありません。

これはエンジンの推論時設定ではありません。ソース全体で環境変数名 `GGUF_DIR` を読む箇所は Docker 起動スクリプトだけで、`setup.py` は環境変数を直接読まず、渡された `--gguf-dir` 引数を処理します。

## 値と判定

| 環境変数 | 起動スクリプトでの扱い |
|---|---|
| 未設定 | `${GGUF_DIR:-}` により空文字になり、`--gguf-dir` を渡さない。セットアップは通常のモデル保管先を使い、必要な shard をダウンロードする。 |
| 空文字 | 未設定と同じ。 |
| 空でない値 | 空白を trim したり書式を検査したりせず、その文字列を1個の引数として `--gguf-dir` の値に渡す。 |

値が空でないかはシェルの `[ -n "$GGUF_DIR" ]` で判定します。たとえば `GGUF_DIR=0` も空でないため有効なフォルダー名として渡されます。空白だけの値もそのまま渡されます。値に `--gguf-dir` のようなオプション書式を入れても、引用された単一の引数なので追加オプションにはなりません。

`setup.py` は引数を `Path(a.gguf_dir)` にし、`--gguf-dir` がある場合はそれをモデルフォルダーとして使います。相対パスは Docker 起動スクリプトが先に `cd /opt/strata` するため、その作業ディレクトリから解決されます。存在しないフォルダーは空き容量確認時に作成されますが、必要な shard が見つからなければセットアップはエラーで停止します。

## 有効になる条件

Docker 起動スクリプトがセットアップを実行する場合にだけ引数として渡されます。次のいずれかのときセットアップ分岐に入ります。

- `REINSTALL=1`。
- 選択中モデルの config ファイルが `$STRATA_DATA/config/strata-<family-model>.json` に存在しない。

ただし `CONFIG` が指定されている場合や、既存の config symlink を保つ分岐に入る場合はセットアップを行わず、`GGUF_DIR` も利用されません。既存 config がある通常の後続起動もセットアップを飛ばすため、この変数を変更しただけでは既存のモデル構成は更新されません。Docker 起動時に `GGUF_DIR` が空でないだけでは再セットアップされず、既存 config に反映するには `REINSTALL=1` などでセットアップ分岐に入る必要があります。

コンテナ外で `setup.py` を直接使う場合は `GGUF_DIR` 環境変数を読みません。既存ファイルを使うには CLI の `--gguf-dir DIR` を指定します。

## 実行時の詳細

セットアップでは指定フォルダーから対象モデルの shard を探します。標準の shard 名がなければ、モデル名を含む `-00001-of-<総数>.gguf` を探し、総数に合わせて shard のパスを組み立てます。ファイル名にモデル名が含まれない候補も、該当する shard が一つだけなら選ばれる場合があります。見つからない shard、GGUF として読めない shard、テンソル配置から計算した必要サイズより短い shard はセットアップ失敗になります。入力フォルダーの既存 GGUF を読むため、モデルのダウンロードは行いません。

`--gguf-dir` を指定した場合、GGUF の `.done` マークがなくても shard がそろっていればモデルファイルが存在すると扱います。ファイルが完全かは GGUF のテンソル情報を使って検査します。書き込み可能なら `.done` マークを作り、読み取り専用共有などで作れない場合は警告を出して処理を続けます。特定の Unsloth shard は、既知のサイズと SHA-256 による追加検証も行います。

`VISION` が有効で、指定フォルダーに vision encoder (`mmproj`) がなければ、その encoder は別途ダウンロードします。したがって `GGUF_DIR` は、すべての追加ファイルを含む任意の完全オフライン指定ではありません。

観測可能なログは、セットアップ時の `Setting up <tag> from the GGUF files in <dir> (the engine is already in the image).` です。GGUF が見つからない場合などの失敗は `setup.py` が `[X]` と理由を表示し、終了コード 1 で停止します。
