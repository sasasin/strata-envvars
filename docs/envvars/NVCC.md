# `NVCC`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。Strata 所有ソースを対象とし、外部コンパイラの挙動は対象外。

## 役割

同梱の DSV41 CUDA kernel lab をビルドする `tools/dsv41_lab/build.sh` が、起動する CUDA コンパイラのコマンドを選びます。このスクリプト内での開発ツール用設定であり、通常の Strata エンジン実行時設定ではありません。選んだコマンドは `tqk_lab` と `ds4_lab` の CUDA コンパイルに使われます（`tools/dsv41_lab/build.sh:2,6-16`）。

## 値と判定

| `NVCC` の状態 | 選ばれる値 |
|---|---|
| 未設定 | `/usr/local/cuda-12.9/bin/nvcc` |
| 空文字 | `/usr/local/cuda-12.9/bin/nvcc` |
| 空でない文字列 | その文字列 |

判定は Bash の `${NVCC:-既定値}` です。値の文字列比較、数値変換、パスの存在確認や妥当性検査はこのスクリプトにはありません。起動時の `$NVCC` は引用符で囲まれていないため、Bash の単語分割と pathname expansion を受けます。空白を含むパスは単一の実行ファイル名として扱われず、ワイルドカード文字も展開対象です。ビルドスクリプトの引数 `$1` は `ARCH` に使われ、`NVCC` を上書きする CLI 引数はありません。選択値は同じスクリプト実行中に変わらず、2 回の CUDA コンパイラ起動に使われます（`tools/dsv41_lab/build.sh:5-6,14,16`）。

## 有効になる条件

`tools/dsv41_lab/build.sh` を実行したときだけ、この選択が行われます。通常の `setup.py` による CUDA エンジンのビルドでは、コンパイラ選択に別名の `STRATA_NVCC` が使われます。`NVCC` はその選択には参照されません（`setup.py:2215-2245`）。

## 実行時の詳細

スクリプトは `set -e` を指定し、スクリプト自身のディレクトリへ移動した後、`ARCH`（既定 `sm_86`）と `NVCC` を設定します。続いて `out` を作成し、4 つの C++ オブジェクトを `g++` でコンパイルしてから、選択した `$NVCC` で `tqk_lab`、次に `ds4_lab` をコンパイルします。したがって、C++ コンパイルが失敗すれば NVCC の起動前にスクリプトが終了し、最初の CUDA コンパイルが失敗すれば 2 回目には進みません（`tools/dsv41_lab/build.sh:3-16`）。

このスクリプト自身は、選んだ値や成功を示す専用ログを出しません。コンパイラ起動の失敗時は `set -e` によりスクリプトが失敗終了します。具体的な診断文や終了コードは起動されたコマンド／シェルの結果であり、Strata は独自の警告や fallback を追加していません（`tools/dsv41_lab/build.sh:3,14,16`）。
