# `STRATA_DS4_REUSE`

調査対象: Strata `main` の HEAD `7dd5cf18e68c639a8773e096c5c79f971ea2a9f5`（2026-10-25 時点）。外部ライブラリとテスト専用コードは対象外。

## 役割

DeepSeek-V4.1 (`maya-ds4`) の `--serve` モードで、直前の会話状態を次の有効なリクエストにそのまま引き継ぐ処理を制御します。無効にすると、リクエスト処理前にモデル状態を `reset()` し、保持中の画像情報も消します。その後、通常のプロンプト先頭一致を使った継続をしないため、会話スロットが無効なら毎回 prompt 全体を読み直します。

ただし、この変数だけでは、`STRATA_DS4_SLOT_KEEP` が有効なときのスロット保存・復元を止めません。リセット後でも一致する会話スロットがあれば復元し、そのチェックポイント以降を読みます。したがって `STRATA_DS4_REUSE=0` は、スロットが有効な構成で「すべての会話再利用を無効にする」設定ではありません。

## 値と判定

値は `std::atoi()` で整数変換し、結果が `0` かどうかで判定します。文字列全体の検証や範囲制限はありません。

| 環境変数の状態・値 | 判定 |
|---|---|
| 未設定 | 有効（既定） |
| 空文字 | 無効（`atoi("")` は 0） |
| 数値として 0 になる値（例: `0`, `+0`, `false`, `abc`） | 無効 |
| 数値として 0 以外になる値（例: `1`, `-1`, `2`, `1suffix`, ` 1`) | 有効 |

`atoi()` は先頭の空白と符号を許し、数字列の後ろは判定に使いません。数字で始まらない文字列は 0 として扱われます。整数範囲外の文字列について、このコードはエラー検査や fallback を行いません。

## 有効になる条件

- `src/dsv41/ds4_main.cpp` の `--serve` 経路だけで読み取られます。通常の `--ids` などによる単発推論では参照されません。
- 環境変数は `serve()` の開始時に一度読み、そのプロセスの要求ループ中は再評価しません。実行中の環境変更は既存プロセスに反映されず、再起動後に再判定されます。
- `STRATA_DS4_SLOT_KEEP` は独立した設定です。サーバーの `child_env()` は DeepSeek-V4.1 用に未指定時 `STRATA_DS4_SLOT_KEEP=1` を設定します。エンジンを直接起動する場合、`STRATA_DS4_SLOT_KEEP` 未設定ならスロットは無効です。
- スロットが有効なら、`STRATA_DS4_REUSE=0` で現在のモデル内状態をリセットした後にも、既存の RAM / ディスクスロットが次の prompt と一致する場合に復元されます。

## 実行時の詳細

リクエスト行の構文確認と画像入力の検証を通過した後、無効設定なら `m.reset()` と `held.clear()` を実行します。続いて現在のモデル token 状態と prompt の共通 prefix を計算します。スロットが無効なら状態は空なので prompt の開始位置 `from` は 0 となり、prompt 全体が処理対象になります。`DONE` の第9フィールドと stderr の prompt 統計は、再利用 token 数としてこの `from` を報告します。

スロットが有効で、現在のモデル状態からの継続に入らないときは `slot_take()` が prompt と保存済み会話を照合します。一致があれば RAM またはスロットフォルダーから状態を復元し、一致した checkpoint 以降だけを読みます。この分岐は `reuse` 判定とは別に実行されます。サーバー起動時の `child_env()` は設定値を環境から継承し、DeepSeek-V4.1 用にスロット設定を補いますが、`STRATA_DS4_REUSE` 自体は書き換えません。

ソースコメントには `STRATA_DS4_REUSE=0` で「every request is a fresh read of its whole prompt」とありますが、スロット復元経路とは整合しません。現在の実装上は「現在のモデル状態からの直接継続を切る」効果として読み、スロットが有効な場合の復元は別に扱う必要があります。
