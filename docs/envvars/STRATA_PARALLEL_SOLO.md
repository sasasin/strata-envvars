# `STRATA_PARALLEL_SOLO`

調査対象: Strata `main` の HEAD `7695859aa13afb248bdb4d36f9b2e95707db079d`（2026-10-13 時点）。外部ライブラリの環境変数は対象外。

## 役割

`--batch` のサーバーで、他の要求が終わって slot 内に一つだけ残った生成要求を solo 経路へ戻す動作を止めます。通常は slot を停止してから solo 経路へ戻り、エンジンが slot の session を引き継いで生成を続けます。この環境変数を文字列 `0` にすると要求は slot 内で続行します。

この設定は、要求の最初から単独で実行するときの solo 経路を無効化するものではありません。対象は一度 batch slot に入った要求が、他要求の終了後に solo 経路へ戻る場合です。

## 値と判定

サーバーは `os.environ.get("STRATA_PARALLEL_SOLO") == "0"` と文字列全体を比較します。

| 環境変数 | 判定 |
|---|---|
| unset | 抑止しない（通常の solo 復帰判定へ進む） |
| `0` | slot から solo への復帰を抑止 |
| 空文字、`00`、`false`、その他 | 抑止しない |

数値変換、大文字小文字変換、前後の空白除去はありません。`os.environ.get` は `_may_go_solo()` の呼び出しごとに評価され、静的キャッシュはありません。

## 有効になる条件

設定が `0` でも、影響するのは以下の条件を満たして slot から solo に戻ろうとする場面だけです。

- サーバーが batch slot で要求を処理中である。
- エンジンが `INFO slot_cache=1` を通知している。
- 埋め込み入力ではなく、残りの生成上限が32 token以上ある。
- その要求が solo 経路へ戻るのは2回未満。
- slot の稼働要求が一つだけで、待機中の要求がない。

これらのいずれかを満たさない場合、この値による分岐に到達しないか、もともと solo 復帰しません。環境変数自体を読むのは `serve/server.py` のサーバー実装です。

## 実行時の詳細

slot からの各生成 token を受け取った後、サーバーは `_may_go_solo()` を評価します。復帰条件が成立し、環境変数が `0` でなければ `BSTOP <slot>` をエンジンに送り、slot の終了後に solo 経路で生成を続けます。環境変数が `0` なら `_may_go_solo()` が `False` を返すため `BSTOP` を送らず、要求は slot 内にとどまります。起動後に Python プロセス内で `os.environ` の値が変更された場合は、次の判定に反映されます。

アプリケーションログや警告をこの設定のために出す処理は確認できません。`docs/BATCHING.md` は、slot cache があるエンジンでは孤立した要求が solo 経路に戻り、`STRATA_PARALLEL_SOLO=0` でその動作を止めると説明しています。資料の説明は実装と一致します。生成速度や品質への測定値は同資料にないため、ここでは記載しません。
