# `STRATA_PREFILL_EQUAL`

調査対象: Strata `main` の HEAD `296b59d2f73c8f04a805df29c2fa97655adace78`（2026-10-14 時点）。Strata 所有ソースを対象とし、外部ライブラリの環境変数は対象外。

## 役割

プロンプトの区間を複数チャンクに分けるとき、末尾だけ短い通常の分割に代えて、ほぼ等しいチャンクサイズを選ぶ opt-in です。主な用途は、生成時のプロンプト用バッファをエキスパートキャッシュから借りる際の必要スロット数と、serve の各 GPU 段に対する貸出・再配置サイズの計算です。環境変数の設定だけで、すべてのプロンプト経路のチャンク分割が変わるわけではありません。

## 値と判定

| 環境変数 | 判定 |
|---|---|
| 未設定 | 無効 |
| 空文字 | 無効（設定済みだが `e[0] == '\0'`） |
| 先頭文字が `1` | 有効。`1`, `10`, `1anything` など |
| それ以外 | 無効。`0`, `true`, ` 1` など |

文字列全体の比較や数値 parse はしません。`getenv()` が非 null であることに加えて先頭の1文字だけを比較します。判定結果は関数内の `static const bool` に保存されるため、その判定が最初に実行された後でプロセス環境を変更しても再評価されません。

根拠: `src/program/generate.cpp:6587`, `sycl/src/program/generate.cpp:6074`。

## 有効になる条件

チャンクの算出関数は、まず通常サイズ `min(max_chunk, round_up_256(tokens))` を求めます。環境変数が有効でも、次のどれかに該当すれば通常サイズを返します。

- `tokens <= 0` または `max_chunk <= 0`。
- 通常分割で1チャンクに収まる（`n <= 1`）。
- 通常分割の最後のチャンクが `Prefill::stream_all_min_tokens()` より短い。

それ以外では `n = ceil(tokens / max_chunk)` とし、`ceil(tokens / n)` を256トークン単位に切り上げ、`max_chunk` を上限として返します。これにより、末尾が十分長い区間では、末尾だけ短い分割より各チャンクが近いサイズになります。算術の上限に近い値では、`+255` によるオーバーフローを避ける分岐があります。

`stream_all_min_tokens()` は別の設定にも依存します。`STRATA_PREFILL_STREAM_MIN` は `std::atoll` の戻り値が0以上ならその値を閾値にし、戻り値が負または未設定なら内部 share 値、さらにそれがなければ1024を使います。従って、この変数の設定がチャンク算出に反映される範囲は同閾値にも左右されます（`src/prefill/prefill.cpp:164-168`）。

根拠: `src/program/generate.cpp:6588-6596`, `sycl/src/program/generate.cpp:6075-6083`。

## 実行時の詳細

単発 generate では、`--prefill` によりチャンク処理が有効で、プロンプトが複数トークンあり、かつキャッシュ貸出を許可していて、ホスト常駐情報と device residency table がある場合に、バッファ貸出計画の後でこの関数を呼びます。算出サイズが現在のチャンクより小さく、貸出スロットが確保できると、そのサイズで貸出を再計算します。固定チャンクでは `o.prefill_chunk` も更新し、`--prefill auto` では貸出の成否を含めて自動チャンクを設定します。貸出がない場合、またはその前提を満たさない場合は、この分岐から環境変数によるサイズ変更は適用されません。プロンプトを処理した後、借りたスロットはエキスパートデータで補充されます。

serve 経路では、各 prompt segment の `tokens` と現在のチャンク上限から貸出サイズを算出し、各参加 GPU の Prefill バッファ再配置に使います。`pf_parts` が空なら貸出処理をしません。分割時の小区間については `split_small` 上限も適用されるため、算出サイズがそのまま使われない場合があります。

Prefill 本体は初期化された `m.T` を上限に `c0 += m.T` で進み、最後の区間だけ `min(m.T, 残り)` です。したがって設定の影響は、呼び出し側が算出サイズを実際のチャンク／バッファサイズに採用する貸出経路に限られます。ソースコメントは、`stream_all_min_tokens()` 以上のチャンクでは GPU に常駐しない全エキスパートをストリームし、未満の末尾チャンクはその区間がルーティングするエキスパートだけを移す、と説明しています。観測できるログには通常の prefill チャンク数・統計や貸出スロット数がありますが、この変数の有効化を示す専用ログは確認できませんでした。

CUDA 系と SYCL の生成ソースに同じ判定・計算と対応する呼び出し箇所があります。generate は `prefill.run(...)` の失敗時にエラーを stderr に出して終了コード1を返します。チャンク形状が変わった場合の性能や token 出力の同一性について、この調査では測定・実行確認していません。

根拠: `src/program/generate.cpp:13165-13210,13232-13260,11476-11532`; `sycl/src/program/generate.cpp:11842-11887,11910-11924,10301-10341`; `src/prefill/prefill.cpp:1082-1121,2178-2183`。

## 資料との照合

`docs/DETAILS.md:283-286` は `STRATA_PREFILL_EQUAL=1` を opt-in とし、通常の「最大サイズのチャンクと短い末尾」から等サイズに近いチャンクへ変える設定として説明しています。現行コードでは、末尾が `stream_all_min_tokens()` 未満なら通常計算へ戻ることと、適用箇所が貸出サイズ／プロンプトチャンク選択に限られることを確認しました。同資料にはこの変数固有の測定条件や性能値はありません。
