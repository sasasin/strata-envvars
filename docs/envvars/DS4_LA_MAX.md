# `DS4_LA_MAX`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。Strata のソースツリーは `git status --short --branch` で `## main...origin/main` となっており、未コミット変更はありませんでした。外部ライブラリ・OS が読む環境変数の動作は対象外です。

## 役割

Metal 版 DS4 実装の stale-router lookahead が、予測した各将来層について CPU lane 側にあると判断した expert を何個まで先読み対象にするかを制限します。上限に達するまで、予測順に expert の3つの行列範囲をバックグラウンド prefetch pool へ登録します。予測や実際のルーティングを変更する値ではなく、先読み候補数の上限です。

## 値と判定

値は `std::getenv("DS4_LA_MAX")` で取得し、設定されていれば `std::atoi` に渡します。環境変数文字列全体の検証、範囲 clamp、エラー報告はありません。

| 設定 | `cap` | 候補選択への効果 |
|---|---:|---|
| 未設定 | 4 | 各将来層につき最大4件を選ぶ |
| 空文字 | 0（`atoi("")`） | 先読み対象を選ばない |
| 数値文字列 | 変換された整数 | 正数なら各層の最大件数になる |
| 数字の後ろに文字がある文字列 | `atoi` が先頭から変換できた整数 | 例: `3abc` は3として扱われる |
| 数値に変換できない文字列 | 0 | 対象なし |
| 0または負数 | その値 | `cpu.size() < cap` が成立しないため対象なし |

`atoi` のため、空白や符号を含む文字列も C の整数変換規則に従い、末尾全体の妥当性は検査されません。整数型で表現できない値について、このコードは明示的な扱いを定めていません。未設定時の4は既定値であり、CLI 引数や別の環境変数による上書き経路はこの変数の読み取り箇所にはありません。

根拠: `src/dsv41/ds4_model.cu:6612-6623`。

## 有効になる条件

この読み取りと機能呼び出しは `STRATA_METAL` ビルド macro の内側にあります。したがって CUDA/HIP 版の同ファイルではこの変数による処理はコンパイルされません。

Metal 版でも、実際に候補を調べるのは次の条件を通った場合です。

- decode window の token 数 `T` が1。
- `DS4_LOOKAHEAD` から得る深さが正数。実装は未設定なら0、設定時は `atoi` 後に `min(d, 2)` を適用します。コメントには既定2とありますが、実装上は未設定時0です（`src/dsv41/ds4_model.cu:6550-6554`）。
- 現在層から先の層を調べる途中で、次層が `nm == 1`、MXFP4 format、`gate_bias` と `gate_w` の両方が非 null であること。いずれかを満たさない層に到達すると、その先の lookahead も終了します。
- 予測された expert index が `0 <= e < nx.n_exp` で、その次層の `slot[e] < 0`（GPU slot に resident でない）であり、まだ上限 `cap` に達していないこと。

上限は各将来層ごとに適用されます。該当する予測がなければ `DS4_LA_MAX` の値を読んでも行列は登録されません。別の変数 `DS4_LOOKAHEAD` が深さを制御し、`DS4_LA_MAX` 自体を CLI やモデル状態が上書きする処理はありません。

根拠: `src/dsv41/ds4_model.cu:6550-6554,10432-10447,10527-10529,6613-6623`。

## 実行時の詳細

GPU が現在層のルーティングを計算する間に、Metal 経路は将来層の gate と routing を使って最大2層先まで expert index を推定します。GPU stream の event `d.ev2` を記録し、現在層のCPU expert候補を組み立てた後に `lookahead_prefetch()` を呼びます。同関数は現在層が単一 shard（`l.nm == 1`）でなければ戻り、CPU lane の実候補と前回予測との一致数を更新します。その後、`la_n <= 0` なら終了し、そうでなければ event の完了を同期してから `DS4_LA_MAX` を読みます。したがって値は初回の有効な先読み処理時に関数内 static 変数へ保存され、実行中の環境変更は再読込されません。

各選択 expert について `mx_mat()` と `mx_part_bytes()` で得た3範囲を `LaPool::push()` に渡し、登録数 `la_issued` を増やします。pool は遅延起動される静的ポインタで、ワーカースレッドが範囲を処理し、キューが64件を超えた場合は古い要求を落とします。この先読み要求はCPU lane の実際のexpert計算とは別の処理です。

`DS4_LA_MAX` 固有の警告・エラー・終了経路はありません。`DS4_CPU_LOG` が有効で lookahead 処理が初期化された場合は、終了時に `lookahead: ... CPU-lane experts were guessed; ... matrices queued` の統計行を stderr に出しますが、上限値そのものは表示しません。CUDA event 同期や prefetch の内部結果に関する説明は Strata 外部の挙動となるため、ここでは述べません。

根拠: `src/dsv41/ds4_model.cu:6555-6587,6592-6623,6600-6604,10432-10447,10527-10529`。
