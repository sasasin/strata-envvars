## 役割

`DOCKER` は、Strata の Docker イメージを実カード上で確認する補助スクリプト `docker/smoke-test.sh` が、ホスト上で Docker CLI を起動するときのコマンド名を指定します。Strata のエンジンやコンテナの設定を変える変数ではありません。スクリプトはコンテナの起動・状態確認・ログ取得・exec・停止・再起動に同じ値を使います（`docker/smoke-test.sh:2-9,12,27-30,37-46,71-80,84-105`）。

## 値と判定

スクリプトは Bash の `${DOCKER:-docker}` を使います。未設定または空文字なら `docker` が選ばれます。空白だけの値は空文字ではないため既定値には戻らず、後続の単語分割でコマンド名がなくなり、呼び出しに失敗します。値の検証、実行ファイルの事前確認、別名への正規化はありません（`docker/smoke-test.sh:10-14,27-30`）。

値は引用符なしの `$DOCKER` としてコマンド位置に展開されます。そのため、空白で分かれた複数の単語はコマンドと引数として渡り、ワイルドカードはファイル名展開の対象になります。展開結果がシェル構文として再解釈されるわけではありません。たとえば `DOCKER='docker --context test'` は各呼び出しに `--context test` を付ける形で使われます（`docker/smoke-test.sh:27-30,37,46,71,84,96`）。

## 有効になる条件

この変数を読むのは `docker/smoke-test.sh` のみです。スクリプトを実行するときにシェル環境から渡されている必要があります。スクリプト冒頭で既定値に置き換え、その後は同じシェル変数を使うため、実行中に環境変数を変更しても再読込されません。CLI 引数や別の Strata 環境変数との優先順位・上書きはありません（`docker/smoke-test.sh:10-14`）。

## 実行時の詳細

この Bash スクリプトは、最初に `$DOCKER rm -f` で既存コンテナを削除しようとします。この失敗は出力を捨てて無視します。続く `$DOCKER run` が失敗すると `FAIL: docker run` を記録し、終了コード 1 で終了します。その後は同じコマンド指定を用いてコンテナ状態とログを調べ、`exec` による monitor/status/connect の確認、停止後の終了コード確認、および `RESTART=1` の場合の再起動を行います（`docker/smoke-test.sh:26-30,33-46,70-89,94-105`）。

スクリプトは stdout と stderr を `tee` 経由で `$OUT/test.log` に記録します。したがって Docker CLI の起動失敗やエラーは、抑制されていない呼び出しではこのログにも現れます。一方、最初の `rm` の出力は抑制されます（`docker/smoke-test.sh:11,15-17,27,30,37-46`）。
