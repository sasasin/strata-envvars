# `DS4_TOKLOG`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。

## 役割

`strata-dsv41` の通常の `--ids` 生成経路で、生成 token 間のレイテンシ分布を stderr に追加出力します。値そのものを解析せず、環境変数が設定されているかだけを見ます。計測・表示用であり、生成方法や token 選択を切り替える処理ではありません。

この実行ファイルは DeepSeek-V4.1 用の独立したターゲットです。CMake では `STRATA_BUILD_DSV41` が既定 OFF であり、機能が組み込まれるのはこのターゲットをビルドした場合です。標準の `strata` 実行ファイル全般に適用される設定ではありません。

## 値と判定

| 状態 | 判定・動作 |
|---|---|
| 未設定 | レイテンシ分布を出力しない |
| 設定あり（空文字を含む） | 生成 token が9個以上なら出力する |
| 設定値の内容 | 読み取り・数値変換・文字列比較をしない。`0`、`false`、任意の文字列も、空文字と同じく「設定あり」として扱う |
| 設定ありだが生成 token が8個以下 | 分布を出力しない |

出力時は、最初に生成された token に対応する計測値を除いたレイテンシ列を昇順に並べ、p50、p95、p99、最大値、平均値と件数を表示します。p50 はソート後の `v[v.size()/2]`、p95 と p99 はそれぞれ `floor(size * 0.95)`、`floor(size * 0.99)` の添字です。表示値はミリ秒単位で小数なしに丸められます。

## 有効になる条件

- `strata-dsv41` がビルドされていること。CMake の `STRATA_BUILD_DSV41` は既定 OFF です。
- `--serve` を指定しない通常の生成経路であること。`--serve` は別の `serve()` 経路へ移り、その経路は token レイテンシの環境変数を参照せず、別形式の `STAT` を出力します。
- 生成数 `--n` が正で、EOS による終了も含めて実際に生成した token が9個以上あること。`--n` の値は `atoi` で読み取られますが、この変数自身は数値として解釈されません。

`--score`、`--profile-run`、`--spec-eval`、画像エンコードなどの他の処理は通常生成ブロックに入らず、この分布出力の対象外です。実装中で `DS4_TOKLOG` を参照する箇所はこの出力条件の一箇所だけです。

## 実行時の詳細

通常生成では、プロンプト処理後の時刻を `t_prev` に保存し、各生成 token の出力直前に `now_ms() - t_prev` を `tok_ms` に追加して `t_prev` を更新します。分布を作るときは `tok_ms.begin() + 1` から末尾までを使うため、プロンプト処理終了から最初の token までの時間は除かれます。残る値は各 token の記録時刻間の差で、最初の token に続く生成の間隔を表します。

環境変数の読み取りは通常生成ループ終了後の出力条件で行われ、値はキャッシュされません。コード中にこの変数を書き換える処理はありません。結果は `fprintf(stderr, ...)` による `token latency ms: p50 ... p95 ... p99 ... max ... mean ... (... tokens)` 形式の1行です。生成 token 自体は別途 stdout に出力されます。
