# `DS4_DUMP_S_NAMES`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。Strata リポジトリの確認時点の状態は `main...origin/main` で、未コミット変更はありません。

## 役割

DeepSeek-V4.1 用の `strata-dsv41` エンジンが出力する中間値ダンプ `DS4_DUMP_S` について、保存する probe 名を絞ります。`DS4_DUMP_S_NAMES` 自体は中間値の計算を切り替えず、ダンプ対象の名前だけを選びます。

この機能は `STRATA_BUILD_DSV41` が有効なときに作られる独立実行ファイル `strata-dsv41` の `src/dsv41/ds4_model.cu` にあります。CMake ではこのビルドオプションは既定で OFF で、`STRATA_HIP_GFX906` の場合もターゲットを作りません。Strata の共通 `strata` 実行ファイルの環境変数としては確認できません（`CMakeLists.txt:906-920`）。

## 値と判定

値は数値や真偽値として parse されません。初回の対象 dump 呼び出しで `getenv()` の文字列を読み、前後にカンマを足した文字列を作り、probe 名を `,名前,` の形で部分検索します（`src/dsv41/ds4_model.cu:1453-1456`）。

| `DS4_DUMP_S_NAMES` | 判定 |
|---|---|
| 未設定 | 内部文字列が空になり、全 probe 名を許可 |
| 空文字 | 内部文字列は `,,` となり、どの probe 名も一致しない |
| `a,b,c` | `a`、`b`、`c` という完全一致の名前だけ許可 |
| 無効そうな文字列・未知の名前 | エラーにはせず、既知の名前と一致しなければその名前のダンプを出さない |

照合は大文字小文字を区別し、空白を除去しません。したがって `a, b` の第2項目は `" b"` として扱われ、`b` とは一致しません。空の項目は実質無視されます。区切り文字や前後空白を含む名前を部分一致させる処理はありません。登録名は呼び出し元の文字列リテラルで渡されます（例: `mix0`, `a_mix`, `q`, `h_in`, `glog`, `ridx`, `cpu_part`, `moe_out`, `h_out`; `src/dsv41/ds4_model.cu:8116-8122,8304-8336,10458-10461,10579-10593`）。

## 有効になる条件

この名前フィルターが参照されるには、`DS4_DUMP_S` が設定され、指定先を `fopen(path, "wb")` で開けている必要があります。さらに、現在の layer が `DS4_DUMP_S_LAYERS` の対象でなければなりません。ダンプファイルが開けない場合や layer が対象外の場合、`dump_s_name()` より前に処理が戻るため、この変数も読み取られません（`src/dsv41/ds4_model.cu:1280-1295,1447-1458,1469-1471`）。

layer の既定対象は `0,1,2,3` です。`DS4_DUMP_S_LAYERS` を設定するとその値から layer 番号を `atoi` で作ったリストに変わります。これは名前フィルターとは別の条件で、CLI 引数による `DS4_DUMP_S_NAMES` の上書きや他変数からの代替値はコード上確認できません（同:1280-1295）。

## 実行時の詳細

`dump_s_name()` 内の `static const std::string` が最初に必要になった時点で環境値を一度だけ読み、以後はそのプロセス内でキャッシュした文字列を使います。したがって、プロセス起動後に環境を変更しても名前選択は更新されません。`Impl` の生成時にはダンプ先と layer リストが別途初期化されます（`src/dsv41/ds4_model.cu:1276-1295,1453-1458`）。

名前または layer が対象外なら `dump_sub()` / `dump_sub_host()` は直ちに戻ります。対象なら device 側データを host にコピーして同期した後、または既に host にある値を、名前・layer・位置・token 数・byte 数のヘッダーと payload として `DS4_DUMP_S` ファイルへ書き、flush します（`src/dsv41/ds4_model.cu:1457-1478`）。したがって、選択されなかった device 側 probe ではダンプ用の device-to-host コピーも行いません。

この環境変数の不正値について警告・エラー・終了処理を行うコードはありません。名前が一致しない場合はその probe のレコードが省かれるだけです。ファイル open 後の `fwrite` / `fflush` の戻り値も検査されていません（同:1469-1478）。
