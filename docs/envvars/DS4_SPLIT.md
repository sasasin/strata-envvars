# `DS4_SPLIT`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。外部ライブラリの環境変数は対象外。

## 役割

DeepSeek V4.1 用の独立エンジン `strata-dsv41` が複数の GPU グループへ割り当てる trunk 層の数を、先頭グループから順に指定します。たとえば `DS4_SPLIT=12,14` は trunk の先頭12層をグループ0、その次の14層をグループ1へ割り当てます。指定分の合計がモデルの trunk 層数に足りない場合、残りは最後の GPU グループに置かれます。

これは通常の Strata エンジンにある一般的な layer-split 設定ではありません。`strata-dsv41` のモデルロード中に一度読み込まれる配置上書きです。

## 値と判定

値全体を数値として検証せず、カンマ区切りの各区間を `std::atoi` で整数化します。`atoi` のため、先頭の空白と符号は受け付け、数字の後ろに続く文字列は無視します。整数として始まらない区間は0になります。大文字小文字の扱いは関係ありません。

| 値 | 結果 |
|---|---|
| 未設定 | VRAM量に基づく初期割り当てを使う。chunked prompt の条件を満たす場合は、後述の自動分割最適化も使える |
| 空文字 | 変数は設定済みとして自動分割最適化を止める。解析する区間はなく、trunk全層が最後のGPUグループへ割り当てられる |
| `12,14` | グループ0に12層、グループ1に14層。指定合計の後に層が残れば最後のグループへ置く |
| `2x, 3` | `atoi` により `2` と `3` として扱う |
| `x,3` / `0,3` / `-2,3` | 先頭グループへの割り当て数が0層となり、次の区間から割り当てる。負数もループ回数が0になる |
| グループ数より多い区間 | GPUグループ数までしか適用しない。余った区間は無視する |
| 指定合計が trunk 層数以上 | trunk の全層を割り当てた時点で終了し、超過分は実質無視される |

各区間の変換後に範囲チェックやエラー報告はありません。末尾のカンマは空区間として追加処理されず、連続するカンマは空区間を0として処理します。数値変換の範囲外入力に対する `atoi` の動作はこの実装で定義・検査されていません。

根拠: `src/dsv41/ds4_model.cu:2195-2207`。

## 有効になる条件

- `strata-dsv41` のビルドが必要です。CMake の `STRATA_BUILD_DSV41` は既定で `OFF` で、CUDA または HIP backend 付きのビルド内で独立実行ファイルを作ります。
- 実際の割り当てには少なくとも一つの認識済み CUDA/HIP GPU と、モデルの trunk 層が必要です。複数グループの構成は、選択 GPU 数、`--tp`、GPU のメモリ容量などから決まります。`--tp` によって一グループに複数 GPU が入る場合、この値が数える単位も個々の GPU ではなくグループです。
- この指定は trunk 層だけを変更します。MTP drafter 層にはこの上書きループを適用しません。モデルの head は最後の trunk 層と同じデバイスに置かれます。
- 変数が設定されているだけで、chunked prompt の自動分割最適化は無効になります。その最適化は `chunk > 0`、GPU グループが2〜6個、かつ `DS4_SPLIT` が未設定の場合に限って走ります。空文字や解釈結果がすべて0の値でも「設定済み」なので最適化を抑止します。
- `chunk` が0以下の場合には、その自動最適化自体が条件外です。`chunk` は別の設定から決まるため、`DS4_SPLIT` が未設定でも自動分割最適化が常に動くわけではありません。

グループは `--tp` の幅でデバイスをまとめ、TP が全 GPU 数と一致しない場合は連続した同容量 GPU をまとめる処理で組み立てられます。実際のグループ数や構成はロード時の GPU 列挙とモデル設定に依存します。

根拠: `CMakeLists.txt:797-811`; `src/dsv41/ds4_model.cu:1877-1886,1899-1947,2036-2044,2151-2152,2195-2213`。

## 実行時の詳細

モデルロード中、まず利用可能 VRAM と重みサイズに基づく初期割り当てを作ります。`DS4_SPLIT` が設定されていなければ、chunked prompt で複数グループを使う一部の条件に限り、各グループの空き容量や層ごとの dense/expert weight 量から最大ストリーミングコストを抑える連続範囲を動的計画法で選びます。その後、`DS4_SPLIT` があれば初期 trunk 配置を上書きし、各層の先頭デバイスとテンソル並列幅を決めます。

明示値は GPU グループの空き容量や重みサイズに合わせて補正されません。指定によるメモリ不足や不適合は、この配置処理では検証されません。後続の重み読み込みや計算で問題になる可能性がありますが、この変数を理由とする専用の警告・エラー・配置ログは確認できません。

評価は `Model::load()` 内の配置処理で行われます。`getenv()` は自動最適化条件の確認と、手動値の解析で参照されます。どちらもモデルロード時の読み取りであり、実行中にプロセス環境を変更して配置を再計算する処理はありません。子プロセスへの引き渡しを行うコードも、この変数については見つかりません。
