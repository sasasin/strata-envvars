# `DS4_INJECT_FATAL_ONCE`

調査対象: Strata `main` の HEAD `ffa80d73133ea5c548aefe57889a16e8085a938f`（2026-11-03 時点）。対象は Strata 所有ソース。外部ライブラリや GPU driver の環境変数動作は扱わない。

## 役割

`strata-dsv41` の fatal GPU error 終了経路を試す診断用フック `DS4_INJECT_FATAL` に、ファイルマーカーによる「再起動をまたいで一度だけ注入する」抑止を加えます。この変数だけではエラーを注入しません。DeepSeek-V4.1 用の別実行ファイル `strata-dsv41` でのみコードが組み込まれ、ビルド時は `STRATA_BUILD_DSV41` が有効で `STRATA_HIP_GFX906` でないことが条件です（`CMakeLists.txt:931-945`）。

## 値と判定

| 値 | Strata の処理 |
| --- | --- |
| 未設定 | マーカー確認・作成をせず、`DS4_INJECT_FATAL` の注入判定に従う |
| 空文字 | `f != nullptr && *f` の条件に合わず、未設定と同じ |
| 空でない文字列 | その文字列をファイルパスとして `fopen` に渡し、マーカーを確認・作成する |

空白除去、値の parse、文字列比較はありません。相対パスの基準ディレクトリの変更もこの処理にはありません。読み取り時に開けたファイルがあれば内容に関係なく注入を抑止します。読み取りで開けなければ書き込みモードで作成を試みます。作成に成功すれば空ファイルができますが、作成に失敗しても関数は注入を許可します。したがって、パスが無効・書き込み不可などでマーカーを作れない場合、「再起動をまたいで一度だけ」は保証されません（`src/dsv41/ds4_main.cpp:403-408`）。

この処理は `DS4_INJECT_FATAL` が注入判定まで到達したときだけ行われます。同変数は `std::atol` で初回に一度読み、未設定なら `0`、正数なら関数呼び出し回数を数え、指定回目だけ注入対象にします。したがって空文字や数値に変換できない文字列は `atol` の結果が 0 となり注入されません。文字列全体の厳密な数値検証はありません（`src/dsv41/ds4_main.cpp:398-402`）。`DS4_INJECT_FATAL` が未設定または正数でなければ、`DS4_INJECT_FATAL_ONCE` の値は読み取られません。

## 有効になる条件

- `strata-dsv41` が上記の CMake 条件でビルドされ、その実行ファイルを起動していること。
- `DS4_INJECT_FATAL` が正数に変換され、注入カウンターがその回数に達すること。
- 対象の要求が prompt 処理の最終 piece に到達すること。途中 piece はそこで戻るため注入判定を通りません（`src/dsv41/ds4_main.cpp:1314-1319`）。
- その呼び出しでマーカーを読み取りオープンできると注入しません。開けない場合は作成を試みたうえで注入します。

マーカーはアトミックな作成ではありません。複数プロセスが同じパスを同時に確認する場合の競合を防ぐ処理はありません（`src/dsv41/ds4_main.cpp:404-407`）。CLI や他の環境変数から、このマーカー処理を上書きする分岐は確認できません。

## 実行時の詳細

注入判定関数にはプロセス内 `static` の回数設定とカウンターがあります。`DS4_INJECT_FATAL_ONCE` はその回数に達した呼び出し時にだけ調べられます。マーカーファイルが既に読み取り可能なら、そのプロセスの当該呼び出しは `false` を返し、fatal 注入を抑止します。ファイルが読めなければ `"wb"` で作成を試し、作成結果にかかわらず `true` を返します（`src/dsv41/ds4_main.cpp:398-408`）。マーカーを残したままエンジンが再起動すると、次のプロセスでも同じパスを確認し、読み取り可能なら注入を抑止します。

注入が許可されると、`die_gpu_fatal` が stderr に `ds4: fatal GPU error (...)`、stdout に `ERR fatal GPU error: ...` を出し、終了コード 3 で即時終了します。注入メッセージは `injected (DS4_INJECT_FATAL): an illegal memory access was encountered` です（`src/dsv41/ds4_main.cpp:390-396,1317-1319`）。サーバーモードではサーバーがこの ERR をエンジン終了として扱い、処理中の要求を再試行可能な 503 として失敗させます。次の要求でエンジンを再起動し、10 分間に fatal 終了が 3 回に達すると、その時間枠では再起動を止めます（`serve/server.py:1782-1791,4965-4991`）。
