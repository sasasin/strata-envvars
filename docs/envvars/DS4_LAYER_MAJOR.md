# `DS4_LAYER_MAJOR`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。外部ライブラリの環境変数は対象外。

## 役割

DeepSeek V4.1 専用エンジン `strata-dsv41` のチャンク化 prompt で、複数チャンクを「チャンクごとに全層」ではなく「層ごとに全チャンク」の順に実行する layer-major 経路を許可・抑止します。layer-major ではチャンク間で層の expert を再利用するためのホスト側 layer cache と、層間でチャンク状態を退避する領域を確保します。環境変数は経路選択のゲートであり、値を有効にしても後述の条件を満たさない run は通常経路になります。

このエンジンは CMake オプション `STRATA_BUILD_DSV41` が有効な場合に別実行ファイルとしてビルドされます（既定 OFF）。CMake では `STRATA_HIP_GFX906` の場合もこの実行ファイルを追加しません。根拠: `CMakeLists.txt:797-811`。

## 値と判定

`lm_begin()` で `std::getenv()` の値に `std::atoi()` を適用し、結果が `0` のときだけ layer-major を抑止します。文字列全体の妥当性検査や範囲チェックはありません。

| 値 | ゲートの判定 |
|---|---|
| 未設定 | 抑止しない（既定で許可） |
| 空文字、非数値、10進数として先頭の数値部分が 0 | `atoi()` が 0 を返すため抑止 |
| 先頭の数値部分が 0 以外 | 抑止しない。負数も 0 以外なら許可 |

`atoi()` は先頭の空白と符号を許し、10進数の数値部分を変換します。たとえば `2tail` は 2、`0tail` は 0、`-1` は -1 と判定されます。`true` や空文字は 0 となり抑止します。整数型で表せない値の扱いは `atoi()` に委ねられています。

## 有効になる条件

ゲートが抑止しなくても、次の条件が必要です。

- 実行時に GPU が1台である。
- 対象 run のチャンク数が2以上である（prompt が複数チャンクに分割されている）。
- その GPU の Chunk が flow 経路である。flow 経路の初期化は `DS4_FLOW`、expert の形式などにも依存します。たとえば flow は既定で許可されていますが、`DS4_FLOW=0` なら無効です。ソースでは flow の対象 expert 形式を MXFP4 に限定しています。
- 層キャッシュに少なくとも最大 expert 1個分の領域を確保でき、必要なホスト領域の割り当ても成功する。
- 再読込を避ける量が、層間で移動するチャンク状態量を上回る。コード上は `(チャンク数 - 1) * file_b > moved` が必要です。

条件を満たさない場合 `lm_begin()` は `false` を返し、`run_dev_chunks()` は通常の chunk-major flow を続けます。GPU 数・チャンク数・flow の判定は `src/dsv41/ds4_model.cu:8091-8093`、再読込と状態移動量の比較・割当条件は同 `:8094-8128`、flow の設定条件は同 `:2704-2738` にあります。

## 実行時の詳細

`DS4_LAYER_MAJOR` は `lm_begin()` の関数内 `static const char*` として、プロセスで初めてこの関数が呼ばれたときに `getenv()` されます。値を `bool` にキャッシュするのではなく、保存したポインターへ各呼び出し時に `atoi()` を適用します。従って後から環境変数を設定しても `getenv()` をやり直しません。環境文字列の実行中変更は、保存ポインターの有効性も含めてサポートされる挙動として確認できません。通常はプロセス起動前に設定してください。

layer-major が選ばれると `run_dev_layers()` は各層について全チャンクを順に処理し、層の中間状態をホスト領域へ退避・復元します。各層の expert 読み込みを次のチャンクで再利用するため、flow の読み込み順もチャンク優先から層優先へ切り替わります。根拠: `src/dsv41/ds4_model.cu:3406-3430,7492-7500,7520-7576,7634-7639`。

`DS4_LAYER_CACHE_MB` は併用変数です。未設定時は利用可能 RAM から余裕分とチャンク状態領域を差し引いて cache 容量を決め、設定時は `atoll()` の結果を MiB に換算した値と必要量の小さい方を使います。明示値が小さく、cache に最大 expert 1個分も入らない場合は layer-major を使いません。確保した pinned host state が使えない場合は pageable 領域へ fallback しますが、その領域または cache の割り当てに失敗すれば通常経路になります。根拠: 同 `:8112-8138`。

この変数自身による有効・無効の専用ログやエラーは確認できません。`-v` または `DS4_FLOW_STATS` を有効にした flow 統計では、layer-major の場合に `, N again from the layer cache (layer-major, ... chunks, ... GB of RAM)` が `ds4 prompt stream` の行に付加されます。通常の統計行は同 `:8385-8405` にあります。
