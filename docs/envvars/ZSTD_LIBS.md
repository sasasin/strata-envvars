# `ZSTD_LIBS`

調査対象: Strata `main` の HEAD `73d4f4196c25a65e02f6b9ef25d354826ce55105`（`2026-11-23` 時点）。

## 役割

`ZSTD_LIBS` は実行時設定ではなく、Hy4-Flash SYCL 実行ファイルをビルドするシェルスクリプト `engine/src/hy4flash/sycl/build_hy4_sycl.sh` が最終リンク時に使うライブラリ引数を上書きする。スクリプトは値を `LIBS` に入れ、`icpx` の引数としてホストオブジェクトと共に渡す。未設定または空文字なら既定の zstd リンカー引数を使う。したがって、この変数自体は生成済み実行ファイルの実行時動作やモデル処理を制御しない（同ファイル: 1-6, 59-70）。

## 値と判定

シェルの `${ZSTD_LIBS:-既定値}` 展開を使う。`:-` は変数が未設定の場合だけでなく空文字の場合にも既定値を選ぶ。非空なら値をそのまま `LIBS` に組み込み、`$LIBS` の非引用展開によりシェルの単語分割を経て `icpx` に渡す。真偽値や数値への変換、文字列全体の妥当性検査はない（同ファイル: 60, 63-68）。

| 条件 | unset | 有効になる値（例） | 無効・既定値になる値（例） |
|---|---|---|---|
| このスクリプトの SYCL ビルド全モード（`fat` / `bmg` / `acm`） | `-L/usr/lib/x86_64-linux-gnu -l:libzstd.so.1` を使う | 空でない任意の文字列をリンカー引数として使用。例: `-L/opt/zstd/lib -lzstd` | 空文字は既定値に戻る。`0`、`1`、`true`、`false` も特別扱いされず、その文字列がリンカー引数になる |

値に `-lpthread -lm` が後置されるため、これらは `ZSTD_LIBS` を設定しても残る。値はスクリプトによる parse を受けず、非引用展開に伴う単語分割・パス名展開の対象になる（同ファイル: 60, 63-68）。

## 有効になる条件

- `engine/src/hy4flash/sycl/build_hy4_sycl.sh` を実行して `strata-hy4-sycl` をビルドする経路でのみ参照される。通常の実行時、CUDA/HIP/Metal のビルドや他の Strata コマンドが読む参照は確認できない（同ファイル: 1-6, 60-68）。
- スクリプトが最終リンク段階まで進む必要がある。`icpx` が無ければ先に終了し、`ARCH_MODE` が `fat` / `bmg` / `acm` 以外なら `ZSTD_LIBS` の展開前に終了する（同ファイル: 16-40, 60-68）。
- `ZSTD_LIBS` と CLI 引数・設定ファイル・他の環境変数との優先順位処理はない。第1・第2 CLI 引数はそれぞれアーキテクチャモードと出力先に使われる。別変数 `ZSTD_INC` はヘッダー検索パスに使われるが、`ZSTD_LIBS` の判定には関与しない（同ファイル: 9-14, 42-43, 60）。

## 実行時の詳細

シェルスクリプトの実行中、オブジェクトのコンパイル後に `ZSTD_LIBS` を展開して `LIBS` を作り、`icpx` の最終リンクコマンドへ渡す。プロセス起動後に親環境を変更しても、すでに開始したシェルの環境値は更新されず、このスクリプト内に再読込や cache はない。子プロセスとして起動される `icpx` には展開後の引数が渡るが、環境変数そのものを設定・転送する処理はない（同ファイル: 52-68）。

## ログと測定値

最終リンク前に `== Building strata-hy4-sycl (<ARCH_MODE>, onemkl=<0|1>) ==` を標準出力へ出す。この表示に `ZSTD_LIBS` の値は含まれない。リンクが成功すると続けて `ls -lh` で生成物を表示する。コンパイルまたはリンクコマンドが失敗すれば `set -e` によりスクリプトはそこで終了し、`icpx` などの失敗内容は各コマンドの出力に委ねられる。変数固有の警告や fallback ログはない（同ファイル: 7, 52-70）。
