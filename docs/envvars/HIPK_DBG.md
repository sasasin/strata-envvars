# `HIPK_DBG`

調査対象: Strata `main` の HEAD `ffa80d73133ea5c548aefe57889a16e8085a938f`（2026-11-03 時点）。

## 役割

HIP の IQ prompt 行列コアカーネル内で、重み decode と WMMA（行列演算）を個別に止める診断用整数ビットマスクです。製品利用時の機能設定ではなく、カーネル内の一部処理を置き換えたり省いたりします。指定すると通常の計算結果は得られません。

## 値と判定

ホスト側で `std::getenv("HIPK_DBG")` を読み、設定されていれば `std::atoi` の戻り値をカーネル引数 `dbg` として渡します。未設定時は `0` です。空文字や数値で始まらない文字列も `atoi` により `0` になります。`atoi` は整数の先頭部分を読むため、先頭空白と符号を許し、数字の後ろの文字列は判定に使いません（例: `2junk` は 2）。全体の文字列比較や明示的な値域検査はありません。整数範囲を超える入力の変換結果は保証されません。

| 値のビット | 効果 |
|---|---|
| `0`（未設定、空文字、変換結果が 0 を含む） | 通常の decode と行列演算を行う。 |
| bit 0 (`1`) | WMMA を止める。通常の出力累算値は初期値 0 のまま出力される。register-weight カーネルでは decode 結果を sink に集約する処理も有効になる。 |
| bit 1 (`2`) | 重み decode を止める。通常カーネルは合成した値を重みデータとして使い、register-weight カーネルは既存レジスタ値を decode 結果の代わりに使う。WMMA 自体は止めない。 |
| bit 2 (`4`) | 通常カーネルだけで、先読み用の重み・入力読み取りを止める。 |
| その他のビット | 上記のビット判定に一致しない分は、この実装では追加効果を持たない。 |

複数ビットを同時に指定できます。たとえば `3` は bit 0 と bit 1 の両方を有効にします。先頭の整数が 0 なら後続文字列に値があっても通常動作です。

## 有効になる条件

- `src/dsv41/ds4_iq_hip.inc` は `STRATA_USE_HIP` が定義された場合だけ実装を有効にします。`ds4_iq.cu` の `launch_set()` も HIP ビルドに限り `hipk::launch()` を呼び、CUDA ではこの設定を読みません。
- HIP 側でも、対象 IQ 型（IQ2_XXS/XS/S、IQ3_XXS/S、IQ4_XS、IQ1_S/M、IQ4_NL）、対応デバイス、`max_rows > 16`、寸法の割り切れ条件、アラインメント条件などを満たし、`hipk::launch()` が専用カーネルを選んだ場合だけ `HIPK_DBG` が影響します。対象外なら `launch_set()` は通常の `set_kernel` 経路へ進みます。
- デバイス判定は gfx12 を既定で許可し、gfx11 は `STRATA_DS4_HIPK` とアーキテクチャに応じて許可します。`STRATA_DS4_HIPK` が `2` の場合は共有メモリ重みカーネルを選ぶため gfx11 では拒否されます。これらは `HIPK_DBG` 自体の値を上書きせず、対象カーネルへ到達するかを決めます。
- `HIPK_CFG` は register-weight カーネルのタイル形状を選びますが、`HIPK_DBG` の判定値とは独立です。

## 実行時の詳細

値は `run()` と `runr()` の各テンプレート特殊化で `static const int` に初回評価結果を保存します。したがって各特殊化で最初に使われた後の環境変更は、その特殊化の後続呼び出しに反映されません。カーネル起動ごとに保存値を引数として渡します。プロセス間の転送や子プロセス向けの処理はありません。

通常の `set_kernel` は bit 1 で decode の代わりに `tid + w` 等の合成コードを使い、bit 0 で WMMA の累算を省略します。bit 2 は先読み関数を早期 return させます。register-weight の `set_kernel_r` は bit 1 で `step_dec()` を呼ばず、現在のレジスタ値を使い、bit 0 で WMMA を省きます。bit 0 のとき decode 値を `sink` に XOR する処理があり、sink が定数に一致する場合にだけ出力を変更するガードがあります（通常は到達しない値との比較です）。

専用カーネルの起動後は `cudaPeekAtLastError()` の結果を返します。失敗時は `hipk::launch()` が false を返し、呼び出し側の `launch_set()` は通常の kernel 経路へ続きます。`HIPK_DBG` による専用ログや警告はありません。ビット 0/1 を使う場合は演算が意図的に省略または置換されるため、出力値を通常の推論結果として扱えません。
