# `STRATA_RUNTIME_PROFILE`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。

## 役割

Strata の Python サーバーが lifeline 経由で子プロセスを起動するとき、プロセス管理用 JSON 記録の `profile` 欄に値を付けます。記録の profile は `strata_control.procs.records(profile=...)` で絞り込みに使われ、保存済みプロファイル単位で残存プロセスを回収する処理に利用されます。変数を読む箇所はサーバー側の `serve/lifeline.py` であり、ネイティブ推論エンジンの計算設定を変える読み取りは見つかりませんでした。

## 値と判定

`os.environ.get("STRATA_RUNTIME_PROFILE") or None` の結果を記録関数へ渡します。文字列の parse、trim、大小文字変換、形式検証はこの読み取り箇所では行いません。

| 環境値 | 記録に渡す値 |
|---|---|
| 未設定 | `None` |
| 空文字 | `None`（空文字列は falsy） |
| 空でない文字列 | その文字列をそのまま渡す。`"0"`、空白だけの値もこの扱い |

通常のサーバー起動では別の CLI 引数や設定値との優先順位はありません。管理ランタイムがサーバーを起動するときは、継承環境を複製した後に `STRATA_RUNTIME_PROFILE` を保存済みプロファイル名 `self.name` で設定し、親から継承した同名値を上書きします。管理ランタイムの名前は `_name()` で `profiles.PROFILE_ID` に照合されます。

## 有効になる条件

- 値の読み取りは `serve.lifeline.popen()` が子プロセス起動後にプロセス記録を作るときに行われます。エンジンのほか、同じ lifeline を使う画像エンコーダーや MCP 子プロセスの記録にも適用されます。
- 管理ランタイムが起動したサーバーは、プロファイル名を環境へ明示設定してから起動するため、そのサーバーが起動する子プロセスの記録にも同名が使われます。管理ランタイム自身がサーバーの記録を書く箇所では、環境変数ではなく `self.name` を直接渡します。
- 環境変数の値によって、プロセス記録ファイルの書き込み先や記録形式は変わりません。非空値があると、その値と一致する profile の記録だけが profile 指定の `records()` / `end_leftovers()` に含まれます。一致しないプロファイルの記録はその絞り込み対象になりません。

## 実行時の詳細

`lifeline.popen()` はまず `subprocess.Popen` で子を開始し、次に現在の Python プロセス環境から profile を読み、`procs.write_record()` に渡します。従って読み取り時点はモジュール import 時ではなく、子プロセスごとの起動後です。値はプロセス環境から都度取得され、ここに static cache はありません。プロセス環境を実行中に変更した場合、以降に起動する子の記録には変更後の値が使われ、既存の記録は書き換えられません。

`write_record()` は `profile` を JSON の `"profile"` フィールドに格納します。識別情報を取得できない場合や `OSError` / `ValueError` で記録できない場合は `None` を返します。さらに呼び出し側は記録処理と reaper thread の開始を `try/except Exception` で囲み、例外を無視します。この記録は安全網として best effort であり、記録失敗を理由に既に開始した子プロセスの起動を失敗扱いにはしません。ここに本変数に固有のログ・警告・終了経路はありません。
