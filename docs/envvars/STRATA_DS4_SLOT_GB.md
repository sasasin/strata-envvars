# `STRATA_DS4_SLOT_GB`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。Strata リポジトリの作業ツリーは `## main...origin/main` で、未コミット変更はありません。外部ライブラリの環境変数は対象外です。

## 役割

DeepSeek-V4.1 エンジンの `--serve` モードで、会話スロット保存フォルダーにある `slot-*.bin` の合計サイズ上限を GiB 単位で指定します。上限を超えると、最も古く使われた保存会話から削除します。フォルダーの整理はサーバー起動時と会話状態のファイル書き込み後に行います。

この変数はスロット機能を有効にしません。スロット保存自体は `STRATA_DS4_SLOT_KEEP` と容量 `STRATA_DS4_SLOT_CAP` に依存します。直接 `maya-ds4 --serve` を起動して値を設定しなければ既定値は 16 GiB、`serve/server.py` 経由では既定値 2 GiB です。

## 値と判定

C++ の `env_num` helper は `getenv()` が null のときだけ既定値を返し、設定されていると `std::atof()` で `double` に変換します。その後、値に `1073741824.0`（2^30）を掛け、`uint64_t` に変換してバイト上限にします。値の全体検査、範囲検査、clamp、変換エラー処理はありません。

| 入力 | エンジンでの扱い |
|---|---|
| 未設定 | 直接起動は `16`、サーバー経由はサーバーが通常 `2` を設定します。 |
| 空文字 | `atof("")` は 0 となり、上限は 0 バイトです。 |
| 数値文字列 | 浮動小数として読まれ、2^30 倍した結果がバイト上限になります。たとえば `0.5` は 0.5 GiB です。 |
| 数値で始まり後ろに文字がある文字列 | `atof` が認識する数値部分を使い、後続文字を検査しません（例: `2GB` は 2）。 |
| 数値として認識できない文字列 | 0 に変換され、上限は 0 バイトです。 |
| 負数・NaN・変換後に `uint64_t` で表せない値 | 範囲検査がなく、浮動小数から整数への変換が表現可能範囲外になる場合の C++ の動作は保証されません。 |

負でない通常の値では CLI による上書きはありません。サーバーの `child_env()` は親プロセス環境を複製し、設定プロファイルの `env` を上書き適用した後、DeepSeek-V4.1 の場合だけ `deepseek_slot_env()` を呼びます。ここでは `setdefault` で `"2"` を補うため、シェル環境またはプロファイルの `env` に同名の値があればそちらが優先されます。空文字も「キーがある」ため保持され、エンジンでは 0 として扱われます。

## 有効になる条件

- `src/dsv41/ds4_main.cpp` の `serve()` が実行されること。通常はモデル読み込み後に `--serve` が指定された場合です。この変数は通常の生成・採点などの非サーバーモードでは読み取られません。
- スロット保存が有効であること。`STRATA_DS4_SLOT_KEEP` が設定され、`atoi` の結果が 0 以外である必要があります。未設定や 0 の場合、`slot_max` は 0 となり、フォルダー初期化もトリミングも行いません。
- スロットフォルダーを作成でき、ディレクトリーとして扱えること。フォルダーが使えない場合は stderr に `ds4 slots: <path> is not writable - conversations are not set aside` と出し、`slot_max` を 0 にしてスロット機能を止めます。

`STRATA_DS4_SLOT_CAP` は RAM に保持できる会話数を制御しますが、フォルダー上限の値を変更しません。`STRATA_DS4_SLOT_MIN` などもスロットを保存する会話の選択に関係しますが、`STRATA_DS4_SLOT_GB` 自体に CLI 引数で優先する設定はありません。

## 実行時の詳細

値は `serve()` の開始時に一度読み取られ、ローカルの `slot_budget` に格納されます。プロセス実行中に環境を書き換えても再読込されません。サーバーではエンジン子プロセスの環境を作る時点で親環境と設定の `env` をまとめ、その値を子プロセスへ渡します。

スロットフォルダーを初期化できると、起動時に既存の有効な `.bin` を読み込み、`slot_trim("")` を呼びます。合計が上限を超えている間、ディスク上のスロットから `used` が最小の会話を削除します。RAM 内の会話やメタファイルは `.bin` 合計の計算対象ではありません。会話をファイルへ書き込んだ後も `slot_trim(path)` を呼びますが、その書き込みで作ったファイルは `keep` 引数で保護されます。そのため、1 件の新規会話だけで上限を超えてもその会話は残り、他に削除可能な古いファイルがなければ上限超過のままになります。

削除が発生すると、stderr とサーバー標準出力の両方へ `ds4 slots:` / `NOTE sessions:` の通知を出し、超過前のサイズ、上限、削除数、残量を表示します。上限以下で削除がなければ、この上限に関する通知はありません。無効な文字列や空文字はエラーにはならず 0 バイト上限になるため、初期化後の起動時整理では通常、既存のディスクスロットが削除対象になります。書き込み失敗や空き容量不足には別の stderr メッセージがありますが、それらはこの環境変数の値判定エラーではありません。
