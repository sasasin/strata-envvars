# `STRATA_SPLIT_HEADROOM_TOL`

調査対象: Strata `main` の HEAD `296b59d2f73c8f04a805df29c2fa97655adace78`（2026-10-14 時点）。

## 役割

SYCL エンジンの複数 GPU `--layer-split auto` が候補の層分割を選ぶとき、最速予測の分割からどの程度遅い候補までを比較対象に含めるかを指定します。その範囲内では、全 GPU のうち最も余裕が少ない GPU に最大の VRAM 余裕を残す候補を優先します。最速候補を選ぶだけの場合に比べ、VRAM を使い切る配置を避けるための許容幅です。

この変数は `sycl/src/program/generate.cpp` の自動分割探索だけにあります。CUDA/HIP 実装や手動指定した分割には、この名前を読む箇所はありません。

## 値と判定

値は `std::atof` で `double` に変換され、候補選択 helper に渡されます。文字列全体の妥当性検査や範囲制限はありません。

| 環境値 | 判定 |
|---|---|
| unset | `0.002`（最速予測時間の 0.2%） |
| 数値文字列 | `atof` の変換結果を許容率として使う。たとえば `0.01` は 1%。 |
| 空文字、数値に変換できない文字列 | `atof` の結果は 0。完全な予測時間同率の候補までを対象にする。 |
| 0 または負数 | helper が `tol > 0` を満たさないため、許容率 0 と同じ扱い。完全な同率候補までを対象にする。 |
| 正数 | 最速予測時間にその率を掛けた分を加えた範囲までを対象にする。 |

`atof` は数値の後ろに続く文字列を検査しないため、たとえば `0.01junk` は `0.01` として変換されます。小数点はロケールの影響を受ける C ランタイムの変換です。許容率に上限はありません。

## 有効になる条件

- `--layer-split auto` を指定し、複数 GPU が検出された場合に限り、自動分割の探索が実行されます。`--layer-split` は server mode 用で、可視 GPU が1台なら自動分割は解除されます。
- 比較機能自体は別変数 `STRATA_SPLIT_HEADROOM` が有効な場合に働きます。同変数は未設定なら有効、設定時は `atoi(value) != 0` の場合に有効です。したがって `STRATA_SPLIT_HEADROOM=0` では本変数の値による候補の再選択は行われません。
- 1件以下の候補しか採点されなかった場合も再選択処理はありません。

## 実行時の詳細

探索中に候補の予測 decode-window 時間を計算し、各候補について、GPUごとの利用可能量からその分割の session 領域と各層の expert 全量を差し引いた最小余裕量も記録します。最速候補の時間を `best_ms`、本変数の値を `tol` とすると、`best_ms + best_ms * max(tol, 0)` 以下の候補が許容集合です。その集合の中から最小余裕量が最大の候補を選びます。余裕量も同じなら予測時間が短い方を選び、両方同じなら先に現れた候補を維持します。

環境値はこの自動分割探索時に読み取られ、関数内に保存する `static` 変数にはなっていません。探索後にプロセス環境を変更しても、決定済みの層配置は変わりません。

選択が通常の最速候補から変わった場合、stderr に両方の `K`、予測時間、最小 VRAM 余裕を含む `layer split auto: K=... instead of K=...` の行が出ます。その後、採用した配置を `layer split auto: K=... - predicted ...` として表示します。選択が変わらない場合、本変数専用のログはありません。

`docs/INTEL_ARC.md` は既定の 0.2% の許容幅を説明し、2枚の Arc Pro B70 と IQ3_S での自動配置と手動 `K=30` の速度差を記載しています。これは文書に記載された特定構成の報告値であり、本変数だけの効果を分離した測定とは確認できません。
