# `DS4_XIN_N`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。外部ライブラリの環境変数は対象外。

## 役割

DeepSeek-V4.1 の CUDA モデル実装にある router 入力ダンプ（`DS4_XIN_DUMP`）について、各 layer から出力する入力ベクトル数の上限を指定します。`DS4_XIN_N` 単独ではダンプを有効にしません。ファイルを開ける `DS4_XIN_DUMP` の指定が必要です。

## 値と判定

`Model::Impl` のメンバー初期化時に `std::getenv` で読み、設定されていれば `std::atoi` で `int` に変換します。未設定時の既定値は `1024` です。`atoi` は文字列全体の厳密な数値検証をしないため、先頭の空白と符号を許し、数値部分の後ろにある文字は変換結果に影響しません。変換可能な数値が先頭にない場合（明示的な空文字を含む）は `0` になります。範囲外の文字列の結果はこのコードで検証・処理していません。

| 値 | ダンプ対象数への効果 |
|---|---|
| 未設定 | layer ごとの上限を 1024 個にする |
| 0 または負数 | `xin_got < xin_n` が成立せず、対象を出力しない |
| 正数 N | layer ごとの出力サンプル数を最大 N 個にする |

## 有効になる条件

- `DS4_XIN_DUMP` が設定され、その値のパスを `fopen(..., "wb")` で開けること。未設定または open 失敗時は `xin_f` が null になり、XIN ダンプ処理は行われません。
- 対象は `src/dsv41/ds4_model.cu` の CUDA モデル実装です。この変数を読む別の backend 実装は確認できませんでした。
- ダンプ処理は chunk 経路の layer 処理にあり、`mi == 0` かつ MTP layer でない場合だけ実行されます。

## 実行時の詳細

各 `Model::Impl` インスタンスのメンバー初期化時に値を読み、そのインスタンス内で保持します。実行中に環境変数を変更しても、保持済みの `xin_n` は再評価されません。layer ごとの出力済みサンプル数はゼロ初期化された `xin_got[64]` で数えます。

条件を満たす chunk では、残り上限と chunk の token 数、32 の最小値を `tk` とします。したがって一度の chunk/layer で最大32サンプルを出力します。`T` 個の router 入力 `c.x` を GPU から host にコピーし、`stride = max(1, T / tk)` として、添字 `min(T - 1, i * stride)`（`i` は 0 から `tk - 1`）の行を選びます。サンプル数を `xin_got` に加算し、layer の累計が `xin_n` に達すると、その layer の以後の chunk は出力されません。よって N は厳密な「先頭 N token」ではなく、chunk ごとに最大32個ずつ選ぶ出力サンプル数の上限です。

出力は各レコードが `u8 layer`, `u16 tk`, 続いて `tk × D` 個の fp32 router 入力値です。ファイルは `wb` で開かれ、当該箇所では書き込みエラーの個別ログはありません。既定値 1024 などの値を表示する専用ログも見当たりませんでした。
