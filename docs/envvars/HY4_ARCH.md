# `HY4_ARCH`

調査対象: Strata `main` の HEAD `73d4f4196c25a65e02f6b9ef25d354826ce55105`（`2026-11-23` 時点）。

## 役割

`tools/hy4/build_hy4_hip_linux.sh` が `strata-hy4` を HIP でビルドするとき、HIP コンパイラへ渡す `--offload-arch` の値を指定する。値は `ARCH` に入り、セミコロンを空白に置き換えた各要素がコンパイルとリンクの引数列に追加される（同ファイル:7,15,34,38）。このスクリプトはビルド専用であり、生成済み `strata-hy4` の実行時動作を変える読み取り箇所は見つからなかった。

## 値と判定

スクリプトは Bash の `${HY4_ARCH:-gfx1201}` を使う。変数が未設定または空文字なら `gfx1201`、それ以外は値をそのまま `ARCH` に格納する（`tools/hy4/build_hy4_hip_linux.sh:7`）。文字列の大小文字、数値としての妥当性、architecture 名としての妥当性は Strata 側で検査しない。

| 条件（build など） | unset | 有効になる値（例） | 無効になる値（例） |
|---|---|---|---|
| Linux 向け HIP ビルドスクリプトを実行 | `gfx1201` を使用 | `gfx1201`、`gfx1201;gfx1100` のような文字列。セミコロンを区切りに各要素を渡す | Strata 独自の無効値判定はない。空文字は無効値として扱わず `gfx1201` に置換。`0`、`true`、`false` も文字列のまま渡す |

`ARCH` は非引用のシェル展開でループに渡されるため、セミコロンだけでなく空白も単語の区切りになり、空の要素はループに渡らない（同ファイル:15）。値を正規化したり、許可リストと照合したりする Strata の処理はない。どの値が HIP コンパイラに受理されるかはこのスクリプトからは判定できない。

## 有効になる条件

- `tools/hy4/build_hy4_hip_linux.sh` を実行すること。このスクリプトは Linux 上での `strata-hy4` HIP ビルド用と記されている（同ファイル:1-3）。
- スクリプト内では ROCm の `clang++` を使い、HIP ソースのコンパイル時と最終リンク時に `OFFLOAD` を渡す（同ファイル:16-19,32-38）。`HY4_ARCH` は通常の Strata エンジンやサーバー起動時には読み取られない。
- `ROCM_PATH` は ROCm の場所を選ぶ別の環境変数で、未設定時は `/opt/rocm`。これは `HY4_ARCH` の値を変更しない（同ファイル:6,16-19）。

## 実行時の詳細

スクリプト開始時に `ARCH` へ一度展開し、その後 `;` を空白に置換した各要素について `--offload-arch=<要素>` を組み立てる（`tools/hy4/build_hy4_hip_linux.sh:5-7,14-15`）。この引数列は `mla_attn.hip.cpp` と `hy4_main.hip.cpp` のコンパイル、および最終リンクに渡される（同ファイル:32-38）。プロセス内で後から環境変数を変えて再読込する処理や、子プロセスへ環境変数を設定し直す処理はない。実行中の変更は、この既に設定された `ARCH` には反映されない。

この環境変数を読むコードは上記スクリプトの一箇所だけだった。アプリの Hy4 判定にある `HY4_ARCH` は環境変数ではなく、文字列 `'hy4flash'` を保持する JavaScript の定数名である（`app/host/server/hy4.mjs:6,8`）。

## ログと測定値

選択した architecture 値を表示する Strata のログはない。ビルドがリンクまで進むと `built <リポジトリ>/build-hy4/strata-hy4` を出力する（`tools/hy4/build_hy4_hip_linux.sh:38-39`）。無効な値に対する Strata 独自の警告やエラーメッセージはなく、コンパイラに渡した後の扱いは本調査の範囲外である。性能測定値は該当なし。
