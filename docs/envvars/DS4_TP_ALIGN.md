# `DS4_TP_ALIGN`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。

## 役割

GGUF を使う DSV41 モデルで `--tp N` によるテンソル並列を要求したとき、各 GPU に割り当てる FFN 幅のアラインメント条件を指定します。条件を満たさない場合、ロード処理は並列幅 `tp` を要求値から 1 ずつ減らします。`DS4_TP_ALIGN` は GPU 数を直接指定する変数ではありません。

## 値と判定

値は `std::atoi` で整数に変換され、`g.ff / tp` がその整数で割り切れるかを検査します。文字列全体の妥当性確認やエラー処理はありません。

| 環境変数の状態 | 使用されるアラインメント |
|---|---:|
| 未設定 | `128` |
| 整数として読める設定値 | `atoi` が返す値（例: `64`, `+32`, `64tail` はそれぞれ 64, 32, 64） |
| 空文字または先頭が数値でない値 | `0` |

`atoi` は先頭の空白と符号を受け付け、数字列以降の文字列は検査しません。`atoi` の返り値が 0 になる値（空文字や非数値など）では、後続の剰余演算の除数が 0 になり得ます。該当する `while` 条件まで評価が進んだ場合の C++ の動作は未定義です。負数も拒否されず、その数で剰余を取ります（非ゼロの負数でも、剰余が 0 かどうかで割り切れるかを判定します）。

## 有効になる条件

- `DS4_TP_ALIGN` の読み取りは `pk.gguf && tp > 1` の場合に限られます。したがって、非 GGUF のパック、または `--tp 1` では効果がありません。
- `--tp` は CLI から指定し、値は `std::atoi` の後に最低 1 へ丸められます。環境変数は `--tp` を置き換えず、適合する並列幅を探す条件の一つです。
- アラインメント条件だけでなく、FFN 幅 `g.ff` が `tp` で割り切れること、FFN の各分割が量子化ブロック幅 `blk` で割り切れること、attention head 数 `g.heads` と出力グループ数 `g.o_groups` が `tp` で割り切れることも必要です。`blk` は既定 32 から開始し、expert の `w2.weight` テンソルから得た GGUF type block 幅の最大値になります。
- `tp` が下げられた場合も、並列数 `l.nm > 1` の layer の分割には別途 `g.ff % 128 == 0` および `g.ff / 128 >= l.nm` の検査があります。これを満たさないとロードは `tensor parallel ...: the heads, output groups or FFN do not split` で失敗します。したがって、`DS4_TP_ALIGN` を小さくしても 128 幅に関係する後段の制約は解除されません。

## 実行時の詳細

読み取りはモデルの `load()` 内で GPU 初期化後に行われます。並列幅 `tp` が 1 より大きく、FFN 幅・ブロック幅・設定アラインメント・head 数・出力グループ数のいずれかが候補 `tp` で割り切れない間、`tp` を 1 減らします。要求幅から変更された場合は stderr に `ds4: tensor parallel N -> M: the experts' B-value blocks split n_ff F no other way (each GPU its own layers)` を出します。

後続処理では、縮小後の `tp` が GPU グループ幅と `par` の判定に使われます。一方、prompt 並列の判定には要求値 `o.tp > 1` も使われるため、`tp` が 1 まで縮小されても `--tp` の要求が 1 より大きければ prompt 側の条件は真になります。環境変数をリクエストごとに読み直す実装ではなく、モデルロードのこの分岐で評価されます。
