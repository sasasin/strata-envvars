# `BASE`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。

## 役割

`BASE` は `docker/smoke-test.sh` 専用の接続先 URL で、スクリプトを実行するホスト上から Docker コンテナの Strata API に `curl` で接続する際の URL 接頭辞です。Strata エンジンやサーバーの実行時設定ではなく、コンテナにも `BASE` という名前では渡されません。スクリプト冒頭の使用例では `http://127.0.0.1:18080` を指定しています（`docker/smoke-test.sh:1-11,40,48-62,98`）。

## 値と判定

| 状態 | 動作 |
|---|---|
| 未設定 | 冒頭の必須値チェック `${BASE:?}` でシェルエラーとなり、スクリプトは処理を続けない |
| 空文字 | 同じく `${BASE:?}` によりエラーとなり、処理を続けない |
| 空でない値 | 内容を検証・変換せず、後続の URL にそのまま連結する |

`set -u` の後に `: "${IMAGE:?}" "${NAME:?}" "${BASE:?}" "${OUT:?}"` を実行します。空白だけの値もこの必須チェックでは空と判定されません。URL scheme、末尾の `/`、空白、その他の形式について独自の検査、trim、正規化、fallback はありません。したがって API パスは値に文字列連結され、例えば末尾 `/` を含めば `/v1/...` の前に追加の `/` が残ります（`docker/smoke-test.sh:10-11,40,49,51,55-62,98`）。

## 有効になる条件

`BASE` を使うのは `docker/smoke-test.sh` を実行するときだけです。同スクリプトはコンテナを起動して API の応答を確認する smoke test と説明されており、`BASE` はホスト側 `curl` の宛先に使います。通常の Strata CLI、モデル設定、backend、GPU driver の動作を制御する条件や、CLI 引数・他の環境変数との優先順位はありません（`docker/smoke-test.sh:1-11,30,40,48-62,98`; `docs/DOCKER.md:296-301`）。

## 実行時の詳細

必須値チェックはスクリプト開始直後に行われます。以後、`BASE` はモデルの起動待ち中と再起動確認中に `GET $BASE/v1/models`、通常の API 確認で同じ models endpoint、chat と tool call で `$BASE/v1/chat/completions` に連結されます。値は環境からスクリプト開始時にシェル変数として取り込まれ、コード中で再代入されません。各 `curl` 実行時にシェルが展開しますが、スクリプト中に値を更新する処理はありません（`docker/smoke-test.sh:11,40,49,51,55-62,98`）。

`BASE` が未設定または空なら必須値チェックで停止します。非空でも接続先が API の応答を返さない場合、起動待ちでは `WAIT` 秒（既定 2400 秒）を超えるまで確認し、`not serving after ...` を記録して Docker のログを表示し、終了コード 1 で終了します。到達後の各チェックが失敗した場合は `FAIL:` を記録して失敗フラグを立て、最終結果を表示してそのフラグを終了コードにします。`BASE` 自体に対する警告や URL 検証ログはありません（`docker/smoke-test.sh:12-13,21-22,33-44,48-68,94-107`）。
