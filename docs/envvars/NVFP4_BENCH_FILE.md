# `NVFP4_BENCH_FILE`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。外部ライブラリの環境変数は対象外。

## 役割

CUDA ビルドで作られる `nvfp4_decode_bench` が、乱数で初期化する expert weight blob の代わりに、指定ファイルから実データを読み込むための変数です。読み込んだ blob は grouped GPU expert decode の時間と出力 hash の測定に使われます。Strata の通常実行ファイルやサーバーがこの変数を読む箇所は、調査対象 HEAD では確認できません。

## 値と判定

| 状態 | 動作 |
|---|---|
| 未設定 | `blobs` は benchmark 内で生成したデータのままです。 |
| 設定あり | 値をファイルパスとして `fopen(fp, "rb")` に渡します。文字列の parse、trim、空文字の特別扱いはありません。 |
| 開けない | stderr に `cannot open <値>` を出し、終了コード `2` で終了します。 |
| 開けたが、完全な blob を一つも読めない | stderr に `<値> holds no whole blob` を出し、終了コード `2` で終了します。 |
| 完全な blob が `G` 個未満 | 読めた blob を先頭から繰り返しコピーして `G` 個にします。 |
| `G` 個以上ある | 先頭 `G` 個を使用し、残りは読みません。 |

値は真偽値ではなくパスです。空文字も「未設定」と同じにはならず、空のパスとして open が試みられます。ファイル形式やサイズのヘッダー検証はありません。選択された型ペアから計算した `L.bytes` バイトずつを一つの blob として読みます。したがって、ファイルの内容と `gu_type` / `d_type` のレイアウトが合っていることは利用側の前提です。

## 有効になる条件

- CMake の `STRATA_ENABLE_CUDA` が有効な構成で `nvfp4_decode_bench` がビルドされている必要があります。この環境変数の読み取りは同ベンチマークの `main` 内だけにあります。
- 対象ファイルには、引数で選んだ型ペアのレイアウトに対応する完全な blob が少なくとも一つ必要です。
- benchmark の既定値は `gu_type=40`、`d_type=40`（NVFP4）ですが、型ペアはコマンドライン引数で変更できます。環境変数のファイル読込処理自体は型ペアに応じて算出された blob サイズを使います。

## 実行時の詳細

ベンチマークはまず `G * L.bytes` のバッファを乱数で埋め、型に応じたデータ調整を行います。その後 `NVFP4_BENCH_FILE` が設定されていればファイルをバイナリ読み取りで開き、`fread` が `L.bytes` 全体を読み切った回数だけ、最大 `G` 個まで先頭から格納します。末尾に完全な blob より短いデータが残っていても、それは blob 数に数えません。少なくとも一つ読めた場合、足りない領域は読み取った先頭 blob 群の反復コピーで埋めます。成功時は stdout に `blobs: <読込数> real from <パス> (cycled to <G>)` と出します。

このバッファを GPU に転送し、`native_expert_grouped` を実行します。出力 hash は実行結果の確認用です。環境変数は `main` のこの段階で一度読み取られ、実行中にファイルや環境を書き換えても、すでに読み込まれた GPU 入力には反映されません。
