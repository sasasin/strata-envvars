# `DS4_STORE_PRELOAD`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。対象は Strata 所有ソース。外部ライブラリや CUDA driver の動作は含めない。

## 役割

DeepSeek V4.1 (DSV41) の RAM expert store が有効なとき、モデルのロード中に利用頻度プロファイル上の hot expert を store に先読みする処理を止めるための opt-out です。unset なら先読み処理を続けます。設定値を数値として読み、`atoi` の結果が 0 の場合だけ先読みをスキップします。

## 値と判定

| 環境変数の状態 | 判定 | 動作 |
|---|---|---|
| unset | 判定式の左辺が false | 先読みをスキップしない |
| 空文字 | `atoi("") == 0` | 先読みをスキップ |
| 設定値の `atoi` 結果が 0 | 0 | 先読みをスキップ |
| 設定値の `atoi` 結果が 0 以外 | 非 0 | 先読みをスキップしない |

文字列全体の厳密な数値検証はありません。`atoi` は先頭の空白と符号を許し、数字列の後の文字を判定に使いません。そのため、たとえば `0`, `00tail`, `+0` はスキップし、`1`, `-1`, `1tail` はスキップしません。数値に変換できない文字列は `atoi` の結果が 0 となり、スキップします。

根拠: `src/dsv41/ds4_model.cu:4748-4752`。

## 有効になる条件

この変数は DSV41 の `preload_store()` でのみ参照されています。`init_store()` が RAM store を作れなければ `store` が null のままなので、変数の値にかかわらず先読みはありません。store は、正の容量が決まり、レイヤーがあり、先頭レイヤーの形式が MXFP4 で、expert がファイル上にあるときに初期化されます。容量は `--ssd-cache` または `DS4_STORE_GB`、自動容量判定などから決まります。

プロファイルの全カウントが 0 の場合も先読みしません。このチェックは環境変数の判定より後です。起動時に読み込まれたプロファイルがない初回実行では、先読み候補を作らず、最初の token 以降の利用でプロファイルが埋まります。

関連する別変数 `DS4_STORE_BG` が文字列として数値 `1` のとき、先頭の同期 preload は最大 48 GB 相当までとなり、残りはモデル ready 後にバックグラウンドで読み込まれます。`DS4_STORE_PRELOAD` が 0 判定なら、この同期・バックグラウンド双方の先読み処理自体が呼ばれません。

根拠: `src/dsv41/ds4_model.cu:2582-2591, 2820-2823, 4578-4611, 4633-4636, 4749-4759, 4771-4795`。

## 実行時の詳細

モデル初期化の終盤で `init_store()` の直後に `preload_store()` が一度呼ばれます。`preload_store()` はまず store の有無とこの環境変数を確認し、続いてプロファイルの合計が正であることを確認します。候補はモデル本体のレイヤーにある、まだ store slot を持たず、プロファイル値が正の expert です。各候補をプロファイル値 ÷ expert blob byte 数の降順で安定ソートし、その順番で `store->preload()` に渡します。したがって、変数は store の容量やプロファイル自体を変更せず、ロード時に行う先読みだけをオン・オフします。

先読みされた件数と容量、所要時間は stderr に `ds4: RAM store: ... read in ...` の行で出ます。環境変数によって先読みを飛ばした場合は、この先読み完了ログも出ません。読み取りはモデル初期化中の呼び出し時に行われ、同じプロセスでも後から環境変数を変更しても、すでに完了したモデルの先読みには影響しません。別モデルの初期化では改めて判定されます。

根拠: `src/dsv41/ds4_model.cu:2820-2823, 4749-4795`。
