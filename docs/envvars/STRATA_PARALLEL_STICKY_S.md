# `STRATA_PARALLEL_STICKY_S`

調査対象: Strata `main` の HEAD `73d4f4196c25a65e02f6b9ef25d354826ce55105`（`2026-11-23` 時点）。

## 役割

並列バッチ処理で、複数スロットに会話が続いているとみなす時間幅（秒）を設定する。判定が真なら、対応するエンジンが対応する `slot_read` 経路で会話の次ターンを保持スロット内で読む候補となり、スロットで処理中のリクエストが単独になっても solo 経路へ戻るのを抑える。実際に次ターンを同じスロットで読むには、空きスロットに会話 prefix が保持され、prefix 長が必要量以上であることも要る（`terminal/serve/server.py:1927-1937,1954-1971,2048-2052,2499-2504`）。

これは `terminal/serve/server.py` のサーバー制御用設定で、エンジンの生成設定やモデル計算値を直接変更するものではない。値は `StrataEngine` クラス本文のクラス属性として評価される（同ファイル `:714,1948`）。

## 値と判定

`os.environ.get("STRATA_PARALLEL_STICKY_S", "20") or 0` の結果を Python の `float()` に渡す。未設定なら文字列 `"20"` が使われ、空文字なら `or 0` によって数値の `0` となる。`_several_chats()` は値が `<= 0` のとき常に偽を返す（`terminal/serve/server.py:1948,1954-1961`）。

| 条件 | unset | 有効になる値（例） | 無効になる値（例） |
|---|---|---|---|
| サーバーモジュールのクラス定義時 | `20` 秒 | `20`, `0.5`, `1e2` など、`float()` が正の有限数に変換できる値 | 空文字、`0`, `-1`, `-0.0`（判定が常に偽）。`true`, `0anything` など数値に変換できない値は無効値として処理されず、`ValueError` になる |

数値文字列全体を `float()` で変換するため、真偽語や数値の後ろに文字が付く値は受け付けない。前後の空白は Python の `float()` が扱う。有限値の検査や clamp はなく、`nan` は比較結果が偽となるため最近使用されたスロットを数えず、`inf` は正の無限大として比較される。これら非有限値を設定することは想定された通常値として検証されていない（同ファイル `:1948,1954-1961`）。

## 有効になる条件

- `generate()` がエンジンの `batch_slots` を認識し、`generate_batched()` に進むこと。`batch_slots` が 0 なら通常の逐次 `generate()` 経路となり、この設定による判定は行われない（`terminal/serve/server.py:960-964,2531-2542`）。
- `_several_chats()` が、`slot_busy[b]` が真か、`time.time() - slot_used[b] <= PARALLEL_STICKY_S` のスロットを 2 個以上数えること。単に設定値が正であるだけでは判定は真にならない（同ファイル `:1954-1961`）。
- スロット内で次ターンを読む場合は、エンジンの INFO に `slot_read` があり、環境変数 `STRATA_SLOT_READ` が文字列 `"0"` でないこと。さらに、リクエストが単独で、embedding 入力でなく、保持スロットの prefix が 512 token 以上一致する必要がある（`SLOT_PREFIX_MIN`。同ファイル `:1950-1952,1963-1971,2048-2052,2426`）。
- スロット処理中のリクエストを solo 経路に戻さない判定は、エンジン INFO の `slot_cache` が真で、`STRATA_PARALLEL_SOLO` が `"0"` でなく、embedding 入力でなく、再移行回数が 2 回未満かつ残り token 枠が 32 以上のときに検討される。さらに `slot_read` と複数会話判定がともに真なら、solo へ戻さない（同ファイル `:1924-1937,2306-2309`）。

この判定は engine INFO の `batch_slots` / `slot_read` / `slot_cache` に依存し、環境変数単独でエンジン機能を有効化するものではない。ソースに OS や GPU backend を直接分岐する条件はなく、対応可否はエンジンが返す INFO によって表現される（同ファイル `:960-964,1950-1952`）。

## 実行時の詳細

環境値は `server.py` のモジュール読み込み中、`StrataEngine` クラス本文を評価するときに一度変換され、クラス属性に保存される。各エンジンインスタンスやリクエストごとに環境を読み直すコードはないため、プロセス実行中に環境変数を書き換えても判定値には反映されない。`_several_chats()` は呼び出しごとに現在時刻とスロット状態を読み、busy スロットまたは最終使用時刻から設定秒数以内のスロット数を数える（`terminal/serve/server.py:1948,1954-1961`）。

`slot_used` は初期化時に各スロット `0.0` で埋められ、ソース内で時刻が更新されるのは、スロットでの生成を終えて solo 経路へ移る分岐である。通常の `BDONE` で処理が終わる経路ではこの時刻を更新しない。そのため設定時間との比較は「最後にスロット処理が完了した時刻」一般ではなく、この移行時刻を使う（同ファイル `:994,2310-2332`）。

CLI の `--batch` / `--slots` / `--parallel` はエンジンに並列数を要求する。サーバー側はエンジンが報告した `batch_slots` を使って並列経路を選び、この環境変数はその経路内のスロット保持・再利用判定に使う（同ファイル `:960-966,2538-2542`）。
