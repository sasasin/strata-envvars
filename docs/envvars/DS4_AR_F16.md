# `DS4_AR_F16`

調査対象: Strata `main` の HEAD `4b9e05a2a806a3fe24f7b2560d98626c37dade35`（2026-10-26 時点）。外部ライブラリの環境変数は対象外。

## 役割

DSV41 エンジンの複数 GPU tensor-parallel all-reduce のうち、3 メンバー以上で使う reduce-scatter/all-gather カーネルを FP16 形式に切り替えます。FP16 カーネルは各メンバーの部分和と集約結果を FP16 に丸めて共有行・和バッファに格納するため、転送量を抑える代わりに all-reduce の数値精度を変えます。これは開発・実験用の opt-in です。

## 値と判定

最初に該当する all-reduce 経路へ入った時に `getenv()` で読み、`std::atoi(e) != 0` で判定します。変数全体を厳密な数値として検証しません。

| 値 | 判定 |
|---|---|
| 未設定 | 無効。通常の FP32 reduce-scatter カーネルを使う |
| 空文字 | `atoi` が 0 を返すため無効 |
| 整数として 0 に変換される値（例: `0`, `abc`, `0tail`） | 無効 |
| 先頭の空白・符号の後に非ゼロの十進整数がある値（例: ` 2`, `+1`, `-1`, `1tail`） | 変換結果が非ゼロなら有効。後続文字列は変換結果に影響しない |

整数に変換できない文字列は 0 扱いです。`atoi` の整数範囲外入力の結果は C ライブラリ上保証されないため、利用可能な値域としては扱えません。値は大文字小文字比較や boolean 文字列の解釈を行いません。

## 有効になる条件

- 実行経路は `strata-dsv41` の CUDA 実装です。ビルド定義では `src/dsv41/ds4_model.cu` と `src/dsv41/ds4_kernels.cu` がこの実行ファイルに含まれます。
- all-reduce のグループが 3 メンバー以上で、reduce-scatter 用の `sums` と `bflags` が存在するときだけ、この変数を読みます。グループ割当て時、3 メンバー以上のグループにそれらのバッファを確保します。
- 1 または 2 メンバーのグループ、および reduce-scatter 条件を満たさない経路はこの設定を参照せず、通常の転送と FP32 加算を使います。
- 変数の値が有効でも、上記経路を通らない実行では効果がありません。CLI・設定ファイルによる上書きはありません。

## 実行時の詳細

`allreduce()` 内の `static const bool` 初期化で一度だけ環境を判定し、そのプロセス内では結果をキャッシュします。プロセス起動後の環境変更は再評価されません。条件を満たすたびに、このキャッシュ済み値に従って `ar_rs16_kernel` または FP32 の `ar_rs_kernel` を CUDA stream に launch します。切替時のログ出力はありません。

FP16 カーネルは各メンバーの部分和を FP16 に丸めてから読み取り、メンバー順に FP32 加算します。各要素は FP16 の有限範囲 ±65504 に飽和させてから変換します。合計も同様に飽和・FP16 丸めされ、その丸め後の値が各メンバーの `x` に書かれます。このためメンバー間で同じ結果を保つ実装ですが、FP32 経路と同一の数値結果を保証する設定ではありません。

ソースコメントはこの形式について「PCIe のバイト数を半分にする」と説明しています。一方、同じ判定行末には「`DS4_AR_F16=0` 以外では有効」とする古いコメントがありますが、現行コードの条件式は未設定時に `false` を返すため、実際の既定値は無効です。`docs/DETAILS.md` にはこの変数を扱う記述を確認できませんでした。性能向上や精度影響の定量値は、今回参照したコード・資料からは確認できません。
