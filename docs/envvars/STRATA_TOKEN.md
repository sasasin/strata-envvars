# `STRATA_TOKEN`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。外部ライブラリ・エンジン側の利用方法は対象外。

## 役割

Strata 本体に `STRATA_TOKEN` 専用の読み取りや用途の分岐はありません。ただし、serve サーバーは親プロセスの環境をエンジン子プロセスへ引き継ぎ、モデル実行設定の `env` マップも環境として渡します。そのため、OS 環境変数または設定 JSON の `env.STRATA_TOKEN` はエンジン起動時に子プロセスへ届きます。Strata がこの値を認証・検証に使うことは確認できません。

## 値と判定

`STRATA_TOKEN` 固有の parse、空文字判定、値域チェック、既定値設定はありません。親プロセス由来の値は環境のコピーに含まれます。設定 JSON の `env` に同じ名前があれば、その値を Python の `str()` で文字列化してコピーへ設定し、親環境の値を上書きします。未設定ならこの名前について Strata は値を追加しません。空文字を含む値に対する特別扱いはありません。

## 有効になる条件

- serve の `--engine strata` 実行経路で、Strata engine の子プロセスを起動するときに環境が渡されます。
- 親プロセス環境からの継承はその環境に値がある場合に限ります。設定 JSON の `env` に名前があれば、親環境に値がなくてもその値を渡します。
- 起動経路で `STRATA_TOKEN` を削除・上書きする専用処理は確認できません。ホストから起動する場合も、ホストがサーバー用環境を作る際に削除するのは `STRATA_API_KEY` です（`apps/host/server/control-runtime.mjs:78-85`）。

## 実行時の詳細

serve サーバーは `child_env()` で `os.environ` を辞書にコピーし、設定の `env` の各キーと値を文字列化して適用します。エンジン起動時にはその環境を `StrataEngine` に渡し、`--serve` 子プロセスの生成に使います（`serve/server.py:3747-3760,9191-9194,9273-9279,1074-1079`）。したがって設定値はサーバー起動後に環境へ読み込まれるのではなく、エンジン起動時にその子プロセスの環境へ反映されます。設定変更は次回のモデル起動から使われます（`serve/runconfig.py:7-8`）。

`STRATA_TOKEN` 自体について Strata 固有のログ、警告、終了・失敗分岐はありません。値を受け取ったエンジンや外部コードがどう扱うかは、この調査の対象範囲からは判断できません。
