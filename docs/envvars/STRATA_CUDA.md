# `STRATA_CUDA`

調査対象: Strata `main` の HEAD `c62d5e3a15b40ea51c96aae9e8d36928965f53ab`（2026-11-01 時点）。

## 役割

`setup.py` の `--cuda` オプションの既定値を与え、NVIDIA 用にモデルのエンジンを CUDA 12 または CUDA 13 のどちらで選ぶか指定します。これは Strata エンジンが直接読む実行時変数ではありません。セットアッププログラムが値を読み、エンジン選択に使います。セットアップで CUDA 12 が選ばれると、そのモデルの構成に `"cuda": 12` が保存され、`engine-cuda12/` のエンジンが選ばれます（`setup.py:9163-9166, 7788-7799, 8066-8071, 10301-10302`）。

## 値と判定

`setup.py` は `default=os.environ.get("STRATA_CUDA") or None` として値を取得します。空文字は `None` と同じ扱いです。環境変数から来た値には、CLI の `choices` による制限が適用されず、後段の選択関数は文字列がちょうど `"12"` または `"13"` のときだけ明示指定として扱います。それ以外は自動選択になります（`setup.py:9163-9166, 1743-1761`）。

| `STRATA_CUDA` | セットアップでの扱い |
|---|---|
| 未設定または空文字 | 自動選択 |
| `12` | NVIDIA の CUDA 12 エンジンを指定 |
| `13` | NVIDIA の CUDA 13 エンジンを指定 |
| `auto`、空白、その他の文字列 | 明示指定として認識されず、自動選択 |

値の strip、小文字化、数値変換はありません。したがって ` 12`、`12 `、`012`、`AUTO` は `12` / `13` と一致せず、自動選択です。CLI で `--cuda` を指定した場合は環境変数由来の既定値を置き換え、CLI 値は `12`、`13`、`auto` に限られます（`setup.py:9163-9166`）。環境変数に無効な文字列を指定しても、このコード経路ではエラーにはならず自動選択へ進みます。

自動選択では、選んだ NVIDIA GPU のうち CUDA 13 が対象にできない Pascal / Volta 世代が含まれる場合は CUDA 12、該当せず NVIDIA driver が CUDA 13 の下限より古く CUDA 12 互換下限以上の場合も CUDA 12、それ以外は CUDA 13 です。明示値 `12` / `13` はこの推奨を上書きします。`13` を指定して古い GPU を選んでもセットアップは選択を拒否せず、CUDA 13 にその GPU 向けコードがない警告を出します。選択後、driver が選んだ engine の下限未満なら `fail(...)` に進みます（`setup.py:1743-1761, 9475-9486`）。

## 有効になる条件

- NVIDIA エンジンを選ぶ新規セットアップまたは `--setup` での再設定では、`STRATA_CUDA=12` / `13` が GPU 世代と driver に基づく自動選択を上書きします。選択はモデル単位です（`setup.py:9475-9486, 7772-7799, 8066-8071, 10301-10302`; `docs/OLDER_GPUS.md:65-88`）。
- `STRATA_CUDA=12` は Pascal / Volta の利用を許可する既存の選択条件にも使われます。ただし、対応 GPU がない場合に CUDA 12 値だけで GPU を利用可能にはしません（`setup.py:1684-1701, 9364-9369`）。
- 既存モデルの通常起動では、保存済み設定を `start(...)` に渡して起動し、`a.cuda` による再選択はありません。環境変数を変えただけでは、そのモデルの engine は切り替わりません（`setup.py:9339-9353`）。新しいモデルのセットアップへ進むときは、そのセットアップ選択に使われます。
- `--rollback-engine` の場合は別用途で、`a.cuda == "12"` なら CUDA 12 側、そうでなければ CUDA 13 側の rollback を呼びます。このとき `STRATA_CUDA=12` があれば CUDA 12 側を選びます（`setup.py:9275-9276`）。
- AMD/HIP のエンジンは `hip` 分岐で選ばれ、CUDA toolkit 選択値は使われません。SYCL は引数解析後に専用セットアップへ移ります。macOS の制御アプリ経路も GPU エンジン選択より前に専用セットアップへ移るため、この変数による CUDA エンジン選択は行いません（`setup.py:9220-9225, 9394-9398, 7772-7799`）。

## 実行時の詳細

値は `main()` 内で引数 parser を構成するときに Python の `os.environ.get` で読み込まれます。プロセス中に環境を変更して再評価する cache はありませんが、同じ `setup.py` の起動中には `a.cuda` として選択処理へ渡されます。`--cuda` の明示指定は parser が環境変数由来の既定値を置き換えます（`setup.py:9163-9166, 9212`）。

NVIDIA のセットアップでは `cuda_choice(...)` が toolkit を決め、`engine_step(...)` が CUDA 12 用の既製エンジンを取得するか、選択 toolkit でエンジンをビルドします。CUDA 12 の場合は構成に `"cuda": 12` を記録します。セットアップは選択理由を `CUDA 12: ...` / `CUDA 13: ...` と表示し、driver 条件を満たさなければ driver が古い旨のエラー経路に進みます（`setup.py:9475-9486, 7772-7799, 8066-8071, 10301-10302`）。通常のモデル起動へ `STRATA_CUDA` を子プロセス環境として転送する処理は、この変数の参照箇所にはありません。

参考文書 `docs/OLDER_GPUS.md` は `STRATA_CUDA=12` を、カード世代を問わず当該モデルに CUDA 12 engine を選ぶ手段として説明しています（`docs/OLDER_GPUS.md:74-94`）。
