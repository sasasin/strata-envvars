# `NEW_RESERVE_MIB`

調査対象: Strata `main` の HEAD `ffa80d73133ea5c548aefe57889a16e8085a938f`（2026-11-03 時点）。

## 役割

同梱の比較用スクリプト `tools/dsv41/bytecheck.sh` で、比較対象の `new` 実行に渡す `--reserve-mib` の値を指定します。モデル実行時に VRAM に残す予約量を変え、空き容量を使った expert の配置を変え得ます。Strata の通常の engine 起動設定として環境変数を読む実装は見つからず、このスクリプト専用の入力です。

## 値と判定

| 状態 | スクリプトが `new` 実行へ渡す値 |
| --- | --- |
| 未設定 | `600` |
| 空文字 | `600`（`${NEW_RESERVE_MIB:-600}` は未設定または null/空のとき既定値を使う） |
| 空でない値 | 値をそのまま `--reserve-mib` の後ろに展開 |

スクリプト側に数値変換や値域検査はありません。値は引用符なしでシェル展開されるため、空白を含む値は複数の引数に分割され得ます。単一の値として実行ファイルに渡すには、空白を含まない整数表記を使います。実行ファイルの CLI は `std::atoll` で10進整数として読みます。したがって、数値で始まらない文字列は `0` になり、整数の後ろにある非数値文字は変換時に無視されます（例: `12MiB` は `12` として扱われます）。符号と先頭空白も `atoll` の変換対象です。CLI に範囲チェックはなく、表現可能範囲外の値の動作はこの実装から保証できません。

スクリプトは `base` 実行では常に `600` を使い、`NEW_RESERVE_MIB` は参照しません。`new` 側ではこの環境変数で既定値 `600` を上書きし、その値を必ず `--reserve-mib` に渡します。CLI オプションを直接指定する呼び出しでは、この環境変数は読み取られません。

## 有効になる条件

- `tools/dsv41/bytecheck.sh` を実行し、`new` 側のコマンドを起動すること。既定の `windows` と `chunked` の比較では各チェックで `new` に一度ずつ使われます。`drafter` を指定した場合も同じです。
- スクリプトの `NEW_RESERVE_MIB` は `base` 側や、他の Strata 起動経路には適用されません。
- スクリプト内で `--no-expert-cache` と `--expert-profile none` を指定しますが、GPU メモリ上の配置量は実行時の空き容量にも依存します。予約値は GPU/モデルの制約を取り除くものではありません。

## 実行時の詳細

スクリプトは `run` 関数で `b=new` のときだけ環境変数を展開し、`"$exe" ... --reserve-mib $reserve` として実行ファイルへ渡します。値はプロセス起動ごとに展開され、Strata エンジン内で環境変数として cache されるものではありません。該当の実行ファイルは `--reserve-mib` を `Options::reserve_mib` に `atoll` で設定します。既定値も 600 MiB ですが、スクリプトは明示的にオプションを渡すため、その CLI 既定値よりスクリプトが渡す値が使われます。

`Options::reserve_mib` は GPU ごとの空き VRAM から差し引かれ、expert 配置用の空き容量や固定予約量の計算に使われます。そのため、`NEW_RESERVE_MIB` を変えると `new` ビルドの配置が変わる可能性があり、スクリプトの説明では、ビルド間で解放された VRAM の差を予約値に加えて expert 配置数を揃える用途を案内しています。特定の値で必ず配置数や出力が一致する保証は、ソースからは確認できません。

各実行の stdout/stderr はそれぞれ `$out/<build>_<check>.out` と `.err` に保存され、スクリプトは標準出力へ `<build> <check> rc=<終了コード>` を表示します。エンジンのモデル読み込み失敗は stderr に `maya-ds4: <理由>` を出して終了コード 1 を返します。スクリプトは `set -u` のみで `set -e` は設定せず、コマンドの終了後に終了コードを表示して比較処理を続けます。最後に logits と標準出力中の token 行を `cmp` で比較し、`IDENTICAL` または `DIFFER` を表示します。
